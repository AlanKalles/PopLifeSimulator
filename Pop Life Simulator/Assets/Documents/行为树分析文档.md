# 顾客行为树分析文档

## 文档概述

本文档分析 Pop Life Simulator 中顾客行为树（CustomerBehaviorTree.asset）的完整执行流程，说明顾客在开店阶段（Open Phase）从生成到销毁的所有行为逻辑。

**关键理解**：
- A* Pathfinding 的多个 Grid Graph 可以重叠而不会互相干涉
- NodeLink2 用于连接**不相连**的寻路区域（如外部街道与商店内部之间的门口）
- 不需要手动管理 graphMask 来分离外部/内部图形

---

## 行为树架构总览

### 树结构层次

```
【根节点 - PrioritySelector】（优先级选择器）
│
├─ 【分支1：应急离店】ConditionalEvaluator (CheckStoreClosingCondition)
│   └─ Emergency Exit Sequencer
│       ├─ ForceExitShoppingLoopAction
│       ├─ ExitStrategy PrioritySelector
│       │   ├─ Rush Checkout（有待结账金额）
│       │   └─ Direct Exit（无待结账金额）
│       └─ Go to Exit Sequencer
│
└─ 【分支2：正常流程】StepIterator（顺序步骤迭代器）
    │
    ├─ 【步骤1】Move To Entrance Sequencer
    │   └─ MoveToEntranceAction
    │
    ├─ 【步骤2】Shopping Circulation Repeater（购物循环）
    │   └─ ConditionalEvaluator (CheckInt: moneyBag > 0)
    │       └─ StepIterator
    │           ├─ check shelf Sequencer
    │           │   └─ ActionList:
    │           │       ├─ SelectTargetShelfAction
    │           │       ├─ AcquireQueueSlotAction
    │           │       ├─ MoveToTargetAction
    │           │       ├─ Wait(0.5s)
    │           │       └─ DecidePurchaseAction
    │           │
    │           ├─ ConditionalEvaluator (purchaseQuantity > 0)
    │           │   └─ ExecutePurchaseAction + Wait(0.2s)
    │           │
    │           └─ ReleaseQueueSlotAction
    │
    └─ 【步骤3】Checkout And Leave Sequencer
        └─ ActionList:
            ├─ SelectCashierAction
            ├─ AcquireQueueSlotAction
            ├─ MoveToTargetAction
            ├─ SkipWaitIfClosingAction
            ├─ ExecuteCheckoutAction
            ├─ ReleaseQueueSlotAction
            ├─ MoveToExitAction
            ├─ SelectExitPointAction
            ├─ SetVariable (hasReachedTarget = false)
            ├─ MoveToTargetAction
            └─ DestroyAgentAction
```

## 完整行为流程分析

### 阶段0：生成准备（Spawn Preparation）

**触发时机**：`DayLoopManager.OnStoreOpen` 事件

**执行者**：`CustomerSpawner.SpawnCustomer()`

**步骤**：
1. 在外部街道的 `SpawnPoint` 位置实例化顾客 GameObject
2. 初始化 `CustomerAgent` 组件
3. 通过 `CustomerBlackboardAdapter` 设置黑板变量：
   ```csharp
   spawnPoint = 生成点Transform         // 最终撤离点
   entranceOutsideAnchor = 门外锚点     // NodeLink2的start点
   entranceInsideAnchor = 门内锚点      // NodeLink2的end点
   moneyBag = Random(walletCap/2, walletCap)  // 钱包金额
   embarrassmentLevel = 0.0f            // 初始尴尬值
   moveSpeed = 基础移动速度              // 来自Archetype
   ```
4. 行为树启动执行

---

### 阶段1：入店流程（Move To Entrance）

**节点类型**：`Sequencer`（顺序执行器）

**子节点**：`MoveToEntranceAction`

#### 执行逻辑

```
【MoveToEntranceAction 内部流程】

1. 验证前置条件：
   ├─ entranceOutsideAnchor != null
   ├─ entranceInsideAnchor != null
   └─ FollowerEntity 组件存在

2. 设置目标位置：
   ├─ destination = entranceOutsideAnchor.position（门外）
   └─ 开始寻路

3. 移动到门外（通过A* Pathfinding）：
   ├─ A* 自动计算路径（SpawnPoint → entranceOutsideAnchor）
   ├─ 顾客按路径移动
   └─ 检测到达：Distance < stoppingDistance (0.1f)

4. 到达门外后切换目标：
   ├─ destination = entranceInsideAnchor.position（门内）
   └─ A* 自动通过 NodeLink2 连接寻路

5. 穿越 NodeLink2：
   ├─ A* 检测到需要通过 NodeLink2
   ├─ 顾客沿 Link 移动（自动处理）
   └─ 进入商店内部图形区域

6. 到达门内：
   ├─ Distance < stoppingDistance
   ├─ hasEnteredStore = true（标记已进店）
   └─ 返回 Success
```

**关键技术点**：
- **NodeLink2 自动穿越**：A* Pathfinding 自动处理跨图形寻路，无需手动编写穿越逻辑
- **两阶段检测**：先到达门外，再通过 Link 到达门内
- **无需 graphMask 管理**：重叠区域的 Grid Graph 不会互相干涉，A* 自动选择最优路径

**失败条件**：
- 超时（默认30秒）
- 目标点不可达
- 组件缺失

---

### 阶段2：购物循环（Shopping Circulation）

**节点类型**：`Repeater`（重复器，repeatTimes=1 表示无限循环）

**循环条件**：`CheckInt: moneyBag > 0`（钱包有余额）

#### 子流程：选择货架并购买

##### 步骤2.1：选择目标货架（check shelf Sequencer）

```
【ActionList 执行序列】

1. SelectTargetShelfAction（选择目标货架）
   ├─ 输入：policies（策略集合，如 WeightedRandomSelector）
   ├─ 调用 TargetSelectorPolicy.SelectTargetShelf()
   ├─ 得分计算公式：
   │   货架得分 = 兴趣匹配 × interestWeight
   │             + 吸引力 × attractivenessWeight
   │             - 队列惩罚(曲线) × queuePenaltyWeight
   │             - 距离惩罚 × distanceWeight
   ├─ 筛选条件：
   │   ├─ 库存 > 0
   │   ├─ 队列长度 < 上限
   │   ├─ 兴趣度 > 阈值
   │   └─ 未购买过该 archetype（防止重复购物）
   ├─ 输出：
   │   ├─ targetShelfId（目标货架实例ID）
   │   └─ goalCell（目标网格坐标）
   └─ 如果无可用货架 → 返回 Failure（退出循环）

2. AcquireQueueSlotAction（获取队列位置）
   ├─ 输入：targetShelfId
   ├─ 调用 ShelfQueueController.RequestSlot()
   ├─ 分配队列位置：
   │   ├─ 位置0 = 队首（interactionAnchor）
   │   └─ 位置1+ = 预设队位或动态计算
   ├─ 输出：assignedQueueSlot（队列位置引用）
   └─ 如果队列已满 → 返回 Failure

3. MoveToTargetAction（移动到货架）
   ├─ 输入：
   │   ├─ assignedQueueSlot.Position（队列位置Transform）
   │   ├─ moveSpeed（移动速度）
   │   └─ stoppingDistance = 0.2f
   ├─ A* 自动寻路到队列位置
   ├─ 队列前移时自动更新目标点
   ├─ 到达检测：Distance < stoppingDistance
   └─ 输出：hasReachedTarget = true

4. Wait（等待0.5秒）
   └─ 模拟浏览货架的时间

5. DecidePurchaseAction（决定购买数量）
   ├─ 输入：
   │   ├─ policies.PurchasePolicy（如 RandomPurchasePolicy）
   │   ├─ targetShelfId
   │   └─ moneyBag（钱包余额）
   ├─ 调用 PurchasePolicy.DecidePurchaseQuantity()
   ├─ 考虑因素：
   │   ├─ 钱包余额（买得起几个）
   │   ├─ 货架库存（有多少库存）
   │   ├─ 顾客兴趣（兴趣越高买越多）
   │   └─ 随机性（增加真实感）
   ├─ 输出：purchaseQuantity（购买数量，可能为0）
   └─ 如果买不起或库存为0 → purchaseQuantity = 0
```

##### 步骤2.2：执行购买（ConditionalEvaluator）

```
【条件判断】purchaseQuantity > 0

如果条件为 true：
  1. ExecutePurchaseAction（执行购买）
     ├─ 输入：
     │   ├─ purchaseQuantity（购买数量）
     │   ├─ targetShelfId
     │   └─ purchaseOneByOne = false（一次性购买）
     ├─ 调用 CustomerInteraction.TryPurchase()
     ├─ 逐件购买逻辑：
     │   for (int i = 0; i < purchaseQuantity; i++) {
     │       1. 查找 ShelfInstance
     │       2. shelf.TryTakeOne() → 扣减库存
     │       3. moneyBag -= price → 扣减顾客钱包
     │       4. pendingPayment += price → 累加待结账金额
     │       5. purchasedArchetypes.Add(archetypeId) → 记录已购买
     │       6. 触发事件：CustomerEventBus.OnCustomerPurchased
     │   }
     ├─ ⚠️ 关键：玩家金钱不变（延迟到收银台结算）
     └─ 记录到 CustomerSession.shelfVisits

  2. Wait（等待0.2秒）
     └─ 模拟付款动画

如果条件为 false（purchaseQuantity = 0）：
  └─ 跳过购买，直接释放队列
```

##### 步骤2.3：释放队列位置

```
【ReleaseQueueSlotAction】

1. 输入：targetShelfId
2. 调用 ShelfQueueController.ReleaseSlot(顾客ID)
3. 队列前移逻辑：
   ├─ 重新分配所有队位
   ├─ 通知后续顾客更新A*目标点
   └─ 更新队列长度统计
4. assignedQueueSlot = null
5. 返回 Success
```

#### 循环退出条件

- `moneyBag <= 0`（钱花光）
- `SelectTargetShelfAction` 返回 Failure（无可用货架）
- 行为树被外部中断（如关店）

### 阶段3：结账与离店（Checkout And Leave）

**节点类型**：`Sequencer`（顺序执行器）

**子节点**：`ActionList`（动作列表）

#### 执行序列

```
【ActionList 执行顺序】

1. SelectCashierAction（选择收银台）
   ├─ 输入：policies.CheckoutPolicy
   ├─ 调用 CheckoutPolicy.SelectCashier()
   ├─ 得分计算：
   │   收银台得分 = -队列长度惩罚
   │               - 距离惩罚
   │               - 预测等待时间惩罚
   ├─ 输出：
   │   ├─ targetCashierId（目标收银台ID）
   │   └─ goalCell（收银台网格坐标）
   └─ 如果无可用收银台 → 返回 Failure（阻塞顾客）

2. AcquireQueueSlotAction（获取收银台队列位置）
   ├─ 输入：targetCashierId
   ├─ 调用 CashierQueueController.RequestSlot()
   ├─ 分配队列位置（同货架队列逻辑）
   └─ 输出：assignedQueueSlot

3. MoveToTargetAction（移动到收银台）
   ├─ 输入：
   │   ├─ assignedQueueSlot.Position
   │   ├─ moveSpeed
   │   └─ stoppingDistance = 0.5f（收银台距离稍大）
   ├─ A* 自动寻路
   ├─ 到达检测
   └─ 输出：hasReachedTarget = true

4. SkipWaitIfClosingAction（关店跳过等待）
   ├─ 检查 DayLoopManager.IsStoreClosing
   ├─ 如果 true → 跳过排队等待动画
   └─ 如果 false → 正常等待队列前移

5. ExecuteCheckoutAction（执行结账）⭐ 关键金钱流转
   ├─ 输入：pendingPayment（待结账金额）
   ├─ 调用 CustomerInteraction.TryCheckout()
   ├─ 结账逻辑：
   │   1. 检查 pendingPayment > 0
   │   2. 记录销售额：DayLoopManager.RecordSale(pendingPayment)
   │   3. ✅ 增加玩家金钱：ResourceManager.AddMoney(pendingPayment)
   │   4. 清空待结账：pendingPayment = 0
   │   5. 触发事件：CustomerEventBus.OnCustomerCheckedOut
   │   6. 更新统计：CustomerRecord.totalSpent += pendingPayment
   ├─ ⚠️ 关键：这是玩家唯一获得金钱的时刻
   └─ 记录到 CustomerSession（结账时间、金额）

6. ReleaseQueueSlotAction（释放收银台队列）
   ├─ 输入：targetCashierId
   ├─ 调用 CashierQueueController.ReleaseSlot()
   └─ 队列前移通知

7. MoveToExitAction（移动到出口）⭐ 离店关键
   ├─ 目标：entranceInsideAnchor（门内）→ entranceOutsideAnchor（门外）
   ├─ 执行逻辑：
   │   【两阶段移动】
   │   阶段1：移动到门内锚点
   │   ├─ destination = entranceInsideAnchor.position
   │   ├─ A* 寻路到门内
   │   └─ 到达检测：Distance < stoppingDistance (0.1f)
   │
   │   阶段2：穿越门口到门外
   │   ├─ destination = entranceOutsideAnchor.position
   │   ├─ A* 自动通过 NodeLink2（反向穿越）
   │   ├─ 到达门外
   │   ├─ hasEnteredStore = false（标记已离店）
   │   └─ 返回 Success
   └─ 关键：NodeLink2 双向通行（oneWay = false）

8. SelectExitPointAction（选择撤离点）
   ├─ 逻辑：targetExitPoint = spawnPoint（回到生成点）
   ├─ 原因：保持向后兼容，最终撤离点 = 生成点
   └─ 输出：targetExitPoint

9. SetVariable（重置到达标志）
   └─ hasReachedTarget = false（准备最后一次移动）

10. MoveToTargetAction（移动回生成点）
    ├─ 输入：
    │   ├─ targetExitPoint（等于 spawnPoint）
    │   ├─ moveSpeed
    │   └─ stoppingDistance = 0.2f
    ├─ A* 在外部街道寻路（已离开商店，在同一个Graph上）
    ├─ 到达检测
    └─ 输出：hasReachedTarget = true

11. DestroyAgentAction（销毁顾客）⭐ 生命周期结束
    ├─ 更新 CustomerRecord 统计：
    │   ├─ visitCount++
    │   ├─ totalSpent += 本次消费
    │   ├─ lastVisitTime = 当前时间
    │   └─ lastVisitReason = "正常离店"
    ├─ 保存 CustomerSession 到记录：
    │   ├─ entryTime, exitTime
    │   ├─ shelfVisits[]（访问的货架列表）
    │   ├─ totalSpent
    │   └─ queueWaitTime
    ├─ 调用 CustomerRepository.SaveRecord()
    ├─ 触发事件：CustomerEventBus.OnCustomerDestroyed
    └─ Destroy(gameObject)
```

## 应急离店流程（Emergency Exit）

### 触发条件

**ConditionalEvaluator**：`CheckStoreClosingCondition`

**判断逻辑**：
```csharp
if (DayLoopManager.CurrentPhase == OpenPhase
    && DayLoopManager.TimeUntilClose < 阈值秒数) {
    return true;  // 触发应急流程
}
```

### 流程分支

#### 分支A：有待结账金额（Priority 1）

**条件**：`CheckPendingPaymentCondition` → `pendingPayment > 0`

```
【Rush Checkout Sequencer】

1. SetUrgentMoveSpeedAction（提升移动速度）
   ├─ moveSpeed *= urgentSpeedMultiplier（如 1.5倍）
   └─ 加速移动动画

2. SelectCashierAction（选择最近收银台）
   └─ 优先选择距离最近的收银台

3. AcquireQueueSlotAction + MoveToTargetAction
   └─ 快速移动到收银台

4. SkipWaitIfClosingAction
   └─ 跳过排队等待动画（立即结账）

5. ExecuteCheckoutAction
   └─ 紧急结账，收取 pendingPayment

6. ReleaseQueueSlotAction
   └─ 释放队列
```

#### 分支B：无待结账金额（Priority 2）

**条件**：`pendingPayment = 0`（未购买任何商品或已结账）

```
【Direct Exit Sequencer】

跳过结账，直接执行：
├─ MoveToExitAction
├─ SelectExitPointAction
├─ MoveToTargetAction
└─ DestroyAgentAction
```

### 共同后续流程

```
【Go to Exit Sequencer】

无论是否结账，最终都会执行：
├─ MoveToExitAction（离开商店）
├─ SelectExitPointAction（选择撤离点）
├─ MoveToTargetAction（回到生成点）
└─ DestroyAgentAction（销毁）
```

## 动画系统集成 ⭐ 新增

### CustomerAnimationController 架构

顾客动画系统通过 `CustomerAnimationController` 组件实现，自动管理所有动画状态的播放和切换。

#### 核心设计

**组件依赖**：
```csharp
CustomerAgent (MonoBehaviour)
├─ Animator                        // Unity 动画组件（必需）
├─ CustomerAnimationController     // 动画管理器（必需）
├─ SpriteRenderer                  // 精灵渲染器（用于翻转朝向）
├─ FollowerEntity (IAstarAI)       // A* 寻路组件（提供速度信息）
└─ CustomerBlackboardAdapter       // 黑板适配器
```

**自动化机制**：
- **Update() 循环**：每帧检测 `IAstarAI.velocity`，自动切换移动/待机动画
- **朝向控制**：根据 `velocity.x` 的正负翻转 `SpriteRenderer.flipX`
- **优先级管理**：单次/循环动画播放时暂停自动切换，动画结束后恢复

---

### 动画状态类型

#### 1. 自动播放的动画（基于移动状态）

##### customer_walk（行走动画）
**触发条件**：`velocity.magnitude > idleThreshold`（默认 0.1）

**朝向控制**：
```csharp
if (velocity.x > 0) {
    spriteRenderer.flipX = false;  // 朝右（默认方向）
} else if (velocity.x < 0) {
    spriteRenderer.flipX = true;   // 朝左（镜像翻转）
}
```

**动画特性**：
- 循环播放
- 自动根据速度播放
- 与 A* Pathfinding 无缝集成

##### customer_idle（待机动画）
**触发条件**：`velocity.magnitude <= idleThreshold`

**动画特性**：
- 循环播放
- 静止时的默认状态
- 可被手动动画打断

---

#### 2. 手动触发的单次动画（One-Shot）

##### customer_pickproduct（拾取商品动画）
**触发时机**：`ExecutePurchaseAction` 成功后

**触发节点**：`PlayPickProductAnimationAction`

**执行逻辑**：
```
1. ExecutePurchaseAction 设置 lastPurchaseSuccessful = true/false
2. PlayPickProductAnimationAction 读取该标志
3. 如果 true → 调用 animController.PlayPickProduct()
4. 如果 false → 跳过动画（购买失败、库存不足、应急离店等情况）
```

**动画参数**：
- 持续时间：0.25 秒
- 播放模式：单次（非循环）
- 播放期间：锁定自动切换，0.25 秒后恢复

**关键设计**：
- 仅在购买成功时播放，避免不合理的动画
- 失败场景：货架无货、策略判断不购买、应急离店且无 pendingPayment

##### customer_checkout（结账动画）
**触发时机**：`ExecuteCheckoutAction` 之后

**触发节点**：`PlayCheckoutAnimationAction`

**执行逻辑**：
```
1. 顾客到达收银台并排队
2. ExecuteCheckoutAction 执行结账（玩家获得收入）
3. PlayCheckoutAnimationAction 播放结账动画
4. 动画播放 0.67 秒后自动恢复
5. 继续执行离店流程
```

**动画参数**：
- 持续时间：0.67 秒
- 播放模式：单次（非循环）
- 播放期间：锁定自动切换，0.67 秒后恢复

---

#### 3. 手动触发的循环动画（Loop）

##### customer_think（思考动画）
**触发时机**：完成一轮购物后，进入下一轮前

**触发节点**：`ThinkBeforeNextShoppingAction`

**执行逻辑**：
```
【ThinkBeforeNextShoppingAction 内部流程】

1. 在当前 Graph 中随机选择可行走位置：
   ├─ 使用 ConstantPath 获取范围内节点（maxMoveDistance = 5 格）
   ├─ 随机选择一个可行走节点
   └─ 如果失败，选择邻近节点或原地思考

2. 移动到思考位置：
   ├─ 设置 destination = 随机位置
   ├─ 开始移动（自动播放 customer_walk 动画）
   └─ 检测到达：Distance <= stoppingDistance (0.5f)

3. 到达后开始思考：
   ├─ followerEntity.isStopped = true（停止移动）
   ├─ animController.PlayThink()（播放思考循环动画）
   ├─ 随机思考时长：Random.Range(0.25f, 0.5f)
   └─ 进入计时状态

4. 思考结束：
   ├─ thinkTimer >= thinkDuration
   ├─ animController.StopLoop()（停止思考动画，恢复 idle）
   ├─ EndAction(true)
   └─ 进入下一轮购物循环
```

**动画参数**：
- 持续时间：0.25-0.5 秒随机
- 播放模式：循环（Loop）

- 应急离店时会跳过整个 `Repeater`，不会卡在 Think 节点
- 随机移动增加顾客行为的自然感
- 短暂思考时间避免影响游戏节奏

### 动画播放优先级

```
【优先级从高到低】

1. 单次动画（One-Shot）
   ├─ customer_pickproduct（0.25秒）
   ├─ customer_checkout（0.67秒）
   └─ 播放期间：isPlayingOneShot = true，锁定自动切换

2. 循环动画（Loop）
   ├─ customer_think（0.25-0.5秒）
   ├─ customer_interaction（2秒，占位）
   └─ 播放期间：isPlayingLoop = true，锁定自动切换

3. 移动动画（Auto）
   ├─ customer_walk（velocity.magnitude > 0.1）
   └─ 自动根据速度播放，可被高优先级动画打断

4. 待机动画（Auto）
   ├─ customer_idle（velocity.magnitude <= 0.1）
   └─ 静止时的默认状态，可被任何动画打断
```

**打断机制**：
- 单次/循环动画播放时，Update() 中的自动切换逻辑被跳过
- 动画结束后（协程或计时器），重置标志位，恢复自动控制
- 中断时（OnStop()），强制停止动画并清理标志位

**优势**：
- 无需两套动画资源（walkright/walkleft）

### A* Pathfinding 集成

#### Grid Graph 配置
```
【外部街道 Graph】
├─ 覆盖商店外部区域
├─ 包含所有 SpawnPoint
└─ Node Size: 1.0-1.5f（中等精度）

【商店内部 Graph】
├─ 覆盖商店一楼及以上楼层
├─ 包含所有建筑（货架、收银台、设施）
└─ Node Size: 0.8-1.0f（较高精度，支持建筑碰撞）

【NodeLink2 连接】
├─ Start: entranceOutsideAnchor（门外，外部Graph）
├─ End: entranceInsideAnchor（门内，内部Graph）
├─ OneWay: false（双向通行）
└─ Cost Factor: 1000（正常代价，不刻意避免）
```

#### 寻路流程
```
顾客请求寻路 → A* 计算路径：
├─ 如果起点和终点在同一个 Graph：
│   └─ 直接计算路径
├─ 如果起点和终点在不同 Graph：
│   ├─ 检测可用的 NodeLink2
│   ├─ 计算通过 Link 的路径成本
│   ├─ 选择最优路径（可能通过多个 Link）
│   └─ 返回完整路径（包含 Link 穿越点）
└─ 顾客沿路径移动（自动处理 Link 穿越）
```

**关键理解**：
- **重叠区域不冲突**：多个 Grid Graph 可以覆盖同一物理空间，A* 会根据节点可达性自动选择合适的 Graph
- **无需手动切换 graphMask**：A* 自动处理跨 Graph 寻路，开发者只需放置 NodeLink2
- **Link 穿越透明化**：顾客移动时自动沿 Link 移动，无需特殊处理

## 关键设计亮点

### 1. 真实的空间流动模拟

**设计理念**：
- 顾客从外部街道生成，走进商店，购物后离开，最终回到街道
- 生成点 ≠ 入口点 ≠ 出口点（但出口点 = 生成点，向后兼容）

**技术实现**：
- 使用 NodeLink2 连接不相连的寻路区域（街道 ↔ 商店）
- A* 自动处理跨区域寻路，无需手动管理 graphMask
- 双向通行（oneWay = false）支持进出

**未来扩展**：
- 多入口支持（前门、后门、VIP入口）
- 入口拥堵控制（限流、队列）
- 地铁站/停车场作为生成点（更真实的城市模拟）

### 2. 两阶段金钱流转系统

**购物阶段**（ExecutePurchaseAction）：
```
顾客操作：
├─ 货架库存 -1
├─ 顾客钱包 -= price
└─ 待结账金额 += price

玩家状态：
└─ 💰 金钱不变（未收到钱）
```

**结账阶段**（ExecuteCheckoutAction）：
```
顾客操作：
├─ 待结账金额 → 0
└─ 记录消费历史

玩家状态：
└─ 💰 金钱 += 待结账金额（真正收到钱）
```

**设计意义**：
- **真实性**：模拟现实购物（先选购，后结账）
- **游戏性**：顾客可能关店前未结账（损失收入）
- **策略性**：需要合理配置收银台数量（避免结账瓶颈）
- **数据追踪**：区分"选购金额"和"实际收入"

### 3. 策略模式驱动的AI决策

**架构优势**：
- **高度可配置**：通过 ScriptableObject 配置不同顾客的决策策略
- **热插拔**：运行时可替换策略（如促销活动改变购买策略）
- **数据驱动**：策略通过快照数据决策，避免直接依赖运行时对象
- **可测试性**：策略是纯函数（输入快照 → 输出决策），易于单元测试

**策略组合示例**：
```
普通顾客：
├─ TargetSelector: WeightedRandomSelector（综合考虑多因素）
├─ PurchasePolicy: RandomPurchasePolicy（随机购买1-3件）
└─ CheckoutPolicy: NearestCashierPolicy（选择最近收银台）

冲动购物者：
├─ TargetSelector: HighAttractivenessSelector（只看吸引力）
├─ PurchasePolicy: ImpulsivePurchasePolicy（大量购买）
└─ CheckoutPolicy: ShortestQueuePolicy（选择最短队列）

理性顾客：
├─ TargetSelector: InterestOnlySelector（只买感兴趣的）
├─ PurchasePolicy: BudgetPurchasePolicy（严格控制预算）
└─ CheckoutPolicy: PredictedWaitTimePolicy（预测等待时间）
```

### 4. 防重复购买机制

**问题**：顾客可能反复在同一类货架购物（不真实）

**解决方案**：
```csharp
// SelectTargetShelfAction 过滤逻辑
var availableShelves = allShelves.Where(shelf => {
    return shelf.currentStock > 0
        && shelf.queueLength < maxQueueLength
        && customerInterest > interestThreshold
        && !purchasedArchetypes.Contains(shelf.archetypeId);  // 关键过滤
});
```

**效果**：
- 顾客不会重复购买同一 archetype 的商品
- 促使顾客探索不同商品类别
- 增加购物路径的多样性

**特殊情况**：
- 如果商店只有单一类别货架 → 顾客买一次后会离开（符合预期）
- 如果商店品类丰富 → 顾客会逛多个货架（真实体验）

### 5. 应急流程的优先级设计

**PrioritySelector 机制**：
```
优先级1（最高）：应急离店
├─ 条件：CheckStoreClosingCondition
├─ 触发时机：关店倒计时 < 阈值
└─ 行为：强制退出购物循环 → 快速结账/离店

优先级2（正常）：正常流程
├─ 条件：商店营业中
└─ 行为：入店 → 购物 → 结账 → 离店
```

**设计意义**：
- **保证游戏流程**：确保所有顾客在关店时能正确离场
- **区分优先级**：有待结账的顾客优先结账，无消费的直接离开
- **性能优化**：关店时跳过等待动画，加速顾客离场
- **避免死锁**：防止顾客卡在商店内导致无法进入下一天

### 6. 队列系统与A*的无缝集成

**队列位置动态更新**：
```
顾客A到达货架队首 → 开始购物
↓
队列控制器移除顾客A → 重新分配所有队位
↓
顾客B的位置：2 → 1（前移）
↓
队列控制器通知顾客B → 更新 assignedQueueSlot.Position
↓
MoveToTargetAction 检测目标变化 → 自动重新寻路
↓
顾客B平滑移动到新位置
```

**优势**：
- **自动化**：队列前移完全自动，无需手动编写移动逻辑
- **响应式**：队列变化立即触发寻路更新
- **兼容RVO**：stoppingDistance 允许局部避障偏移，不会卡住

### 7. 模块化的行为树结构

**StepIterator 的使用**：
```
【正常流程】StepIterator（顺序步骤迭代器）
├─ 步骤1：Move To Entrance（完成后进入下一步）
├─ 步骤2：Shopping Circulation（完成后进入下一步）
└─ 步骤3：Checkout And Leave（完成后结束）

vs.

【传统 Sequencer】（顺序执行器）
└─ 子节点全部执行完才返回 Success
```

**StepIterator 优势**：
- 可以在任意步骤被中断（如应急流程触发）
- 支持更复杂的状态管理（每步可有独立状态）
- 便于调试（可以看到当前执行到哪一步）

## 性能优化要点

### 已实现优化

1. **对象池思想**：
   - 队列位置 Transform 缓存（`cachedSlotTransforms`）
   - 避免频繁创建/销毁 Transform

2. **快照模式**：
   - 策略使用不可变快照，避免锁定运行时对象
   - 批量构建快照（一次性构建所有货架快照）

3. **事件驱动**：
   - 队列前移使用事件通知，避免轮询检查
   - 黑板变量变化自动触发行为树响应

4. **延迟结算**：
   - 购物时仅累加 `pendingPayment`，结账时统一处理
   - 减少频繁的 ResourceManager 调用

### 建议优化

1. **顾客对象池**：
   ```csharp
   // 当前：每次 Instantiate + Destroy（GC压力）
   Destroy(gameObject);

   // 优化：对象池复用
   CustomerPool.Return(gameObject);
   ```

2. **异步寻路**：
   ```csharp
   // 当前：同步计算路径（可能卡顿）
   path = AstarPath.active.GetNearest(target);

   // 优化：异步寻路
   AstarPath.StartPath(start, end, OnPathComplete);
   ```

3. **LOD系统**：
   ```csharp
   // 屏幕外顾客降低更新频率
   if (!IsVisible(camera)) {
       updateInterval = 0.5f;  // 每0.5秒更新一次
   } else {
       updateInterval = 0.1f;  // 正常更新
   }
   ```

4. **空间分割**：
   ```csharp
   // 大量顾客时使用四叉树优化碰撞检测
   QuadTree<CustomerAgent> spatialIndex;
   var nearbyCustomers = spatialIndex.Query(position, radius);
   ```

5. **批量操作**：
   ```csharp
   // 批量处理寻路请求
   var pathRequests = customers.Select(c => c.destination).ToArray();
   AstarPath.StartMultiPathBatch(pathRequests, OnBatchComplete);
   ```

## 已知限制与未来计划

### 当前限制

1. **单一入口设计**：
   - 所有顾客通过同一个 NodeLink2 进出
   - 高峰期可能出现入口拥堵

2. **未实现的策略**：
   - `QueuePolicy`（排队换线策略）
   - `PathPolicy`（重新寻路策略）
   - `EmbarrassmentPolicy`（尴尬值计算策略）

3. **有限的应急逻辑**：
   - 仅处理关店场景
   - 未处理其他应急情况（如火灾、抢劫）

4. **队列容量固定**：
   - 队列上限硬编码
   - 未根据货架/收银台等级动态调整

5. **缺少社交互动**：

## 总结

### 核心流程概括

**顾客完整生命周期**：
```
外部生成 → 走向门口 → 穿过NodeLink2进店 → 循环购物（选货架→排队→购买）
→ 选择收银台 → 排队结账 → 真正获得收入 → 穿过NodeLink2离店
→ 走回生成点 → 数据持久化 → 销毁GameObject
```

### 关键技术栈

| 技术 | 应用 | 优势 |
|------|------|------|
| **NodeCanvas行为树** | 顾客AI决策流程 | 可视化编辑、状态管理清晰 |
| **A* Pathfinding** | 寻路与移动 | 自动处理跨区域寻路、NodeLink2穿越 |
| **Animator动画系统** ⭐ 新增 | 顾客动画播放 | 自动移动动画、朝向翻转、优先级管理 |
| **ScriptableObject策略** | AI决策策略 | 数据驱动、热插拔、易测试 |
| **事件总线** | 系统间通信 | 解耦、易扩展 |
| **队列系统** | 货架/收银台排队 | 真实模拟、自动前移、A*集成 |
| **快照模式** | 策略数据隔离 | 不可变数据、线程安全、性能优化 |
| **JSON持久化** | 顾客数据保存 | 人类可读、易于调试、支持热更新 |

### 设计哲学

1. **真实性优先**：模拟真实购物流程（从街道进入 → 购物 → 结账 → 离开）
2. **数据驱动**：通过配置而非代码控制行为（策略模式 + ScriptableObject）
3. **模块化**：清晰的系统边界（寻路、队列、策略、事件互不耦合）
4. **可扩展性**：为未来功能预留接口（多入口、社交、情绪、动态事件）
5. **性能意识**：对象池、快照、批量操作、LOD系统（部分待实现）

### 架构评价

**优点**：
- ✅ 行为树结构清晰，易于理解和调试
- ✅ 策略模式应用得当，AI高度可配置
- ✅ NodeLink2使用正确，无需手动管理graphMask
- ✅ 两阶段金钱流转真实且有游戏性
- ✅ 队列系统与A*无缝集成
- ✅ 事件系统解耦良好
- ✅ 数据持久化完善，支持长期玩家关系
- ✅ 动画系统自动化，朝向翻转智能，视觉表现自然 ⭐ 新增

**改进空间**：
- ⚠️ 缺少顾客对象池（GC压力）
- ⚠️ 部分策略未实现（Queue/Path/Embarrassment Policy）
- ⚠️ 缺少社交互动系统
- ⚠️ 缺少情绪系统
- ⚠️ 应急流程单一（仅处理关店）
- ⚠️ 多楼层支持有限（无电梯系统）

**总体评分**：⭐⭐⭐⭐☆ (4.5/5)

这是一个设计优秀、架构合理、扩展性强的顾客AI系统，核心流程完整且真实，为后续功能扩展打下了坚实的基础。建议优先实现对象池优化和补充未实现的策略，然后逐步添加社交、情绪等高级功能。
