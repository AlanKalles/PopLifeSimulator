# 建筑透视系统 (Sorting Order System)

## 概述
本文档说明游戏中建筑的透视关系渲染系统，确保建筑按照正确的空间关系进行遮挡显示。

## 设计目标
实现从左到右的透视关系：**右侧的建筑遮挡左侧的建筑**。

## 技术实现

### 核心组件

#### 1. SortingOrderUtility（工具类）
**位置**: `Assets/Scripts/Utility/SortingOrderUtility.cs`

**功能**:
- 根据网格坐标计算建筑的 sorting order
- 更新建筑GameObject上所有SpriteRenderer的sorting order

**计算公式**:
```csharp
sortingOrder = BASE_ORDER + (floorId × 10000) + (gridX × 10) + (gridY × 1)
```

**参数说明**:
- `BASE_ORDER = 100`: 基础排序值，确保建筑在背景之上
- `floorId × 10000`: 楼层偏移，确保不同楼层建筑不会互相遮挡
- `gridX × 10`: X坐标偏移（主要排序依据）
  - X越大（越靠右），sorting order 越高，渲染越靠前
  - 增量为10，为Y方向留出排序空间
- `gridY × 1`: Y坐标偏移（次要排序依据）
  - Y越大（越靠上），sorting order 越高
  - 同一X坐标的建筑，上方建筑会稍微遮挡下方建筑

**示例**:
```
楼层0，位置(3, 1)的建筑: 100 + 0 + 30 + 1 = 131
楼层0，位置(5, 2)的建筑: 100 + 0 + 50 + 2 = 152 (会遮挡前者)
楼层1，位置(3, 1)的建筑: 100 + 10000 + 30 + 1 = 10131 (不同楼层)
```

#### 2. BuildingInstance.UpdateSortingOrder（实例方法）
**位置**: `Assets/Scripts/Runtime/BuildingInstances.cs:118-121`

**功能**:
- 调用 `SortingOrderUtility` 更新自身的 sorting order
- 自动处理建筑上所有的 SpriteRenderer（包括子对象）

**调用时机**:
1. **初始化**: `Initialize()` 方法中（建筑被放置时）
2. **移动**: `FloorGrid.MoveBuilding()` 后（同楼层移动）
3. **跨楼层移动**: `FloorGrid.RegisterExistingBuilding()` 后（跨楼层移动）
4. **加载存档**: `LoadFromSaveData()` 后

### 集成点

#### FloorGrid.InternalInstantiate (306-315行)
建筑实例化时，会调用 `BuildingInstance.Initialize()`，其中会自动设置 sorting order。

#### FloorGrid.MoveBuilding (361-387行)
同楼层移动建筑后，会调用 `bi.UpdateSortingOrder()` 更新排序。

#### FloorGrid.RegisterExistingBuilding (414-441行)
跨楼层移动建筑后，会调用 `bi.UpdateSortingOrder()` 更新排序。

## 使用指南

### 自动处理场景
以下场景会**自动更新** sorting order，无需手动干预：
- ✅ 放置新建筑
- ✅ 移动建筑（同楼层或跨楼层）
- ✅ 加载游戏存档

### 手动更新场景
如果需要在特殊情况下手动更新，可以调用：
```csharp
buildingInstance.UpdateSortingOrder();
```

### 预制体设计注意事项

#### 1. 初始 Sorting Order
建筑预制体上的 SpriteRenderer 可以设置**相对偏移值**（0-999）：
- `0`: 建筑主体
- `1`: 建筑装饰层1
- `2`: 建筑装饰层2
- 以此类推...

系统会保留这些相对偏移，确保建筑内部的层级关系不变。

**示例**:
```
预制体设置:
  - 主体 SpriteRenderer: sortingOrder = 0
  - 装饰 SpriteRenderer: sortingOrder = 1

实际运行时（假设建筑在 (5, 2)）:
  - 主体: 152 (= 100 + 50 + 2 + 0)
  - 装饰: 153 (= 100 + 50 + 2 + 1)
```

#### 2. 避免的设置
❌ **不要**在预制体中设置过大的 sortingOrder（>= 1000）
- 系统会将 >= 1000 的值重置为 0
- 这是为了避免与自动计算的值冲突

✅ **推荐**使用 0-10 范围内的相对偏移值

## 性能考虑

### 优化措施
1. **按需更新**: 只在位置改变时更新 sorting order，而非每帧更新
2. **批量处理**: 一次性更新建筑上所有 SpriteRenderer
3. **缓存计算**: 基础公式简单，计算开销极小

### 性能影响
- **初始化成本**: 每个建筑实例化时一次性计算，开销可忽略
- **运行时成本**: 仅在移动建筑时更新，频率极低
- **内存成本**: 无额外内存开销（不存储额外数据）

## 扩展指南

### 调整透视关系
如果需要调整遮挡规则，可修改 `SortingOrderUtility` 中的常量：

```csharp
// 当前实现：右侧遮挡左侧
private const int X_INCREMENT = 10;  // X越大，sortingOrder越高
private const int Y_INCREMENT = 1;   // Y越大，sortingOrder越高

// 如果需要改为左侧遮挡右侧（不推荐）：
private const int X_INCREMENT = -10; // X越大，sortingOrder越低
```

### 多楼层支持
当前系统已支持多楼层（每层间隔10000个排序值）：
- 楼层0: 100 - 9999
- 楼层1: 10100 - 19999
- 楼层2: 20100 - 29999
- ...

可支持最多 **6553 个楼层**（Unity sortingOrder 上限为 32767）。

## 常见问题

### Q1: 为什么我的建筑没有正确遮挡？
**A**: 检查以下几点：
1. 确保 SpriteRenderer 在正确的 Sorting Layer 上
2. 确认建筑是否已调用 `Initialize()` 或 `UpdateSortingOrder()`
3. 检查预制体上的初始 sortingOrder 是否 < 1000

### Q2: 旋转建筑后遮挡关系变了？
**A**: 这是**正常行为**。sorting order 仅基于网格位置（gridPosition）计算，与旋转无关。如果建筑旋转后占用了不同的网格位置，遮挡关系会相应改变。

### Q3: 多个建筑占用同一X坐标时如何排序？
**A**: 系统使用 Y 坐标作为次要排序依据。**上方的建筑会稍微遮挡下方的建筑**（Y越大，sortingOrder越高）。

### Q4: 能否实现等距视角（isometric）排序？
**A**: 可以。修改 `SortingOrderUtility.CalculateSortingOrder()` 公式：
```csharp
// 等距视角：根据 Y - X 的值排序（越靠后越高）
return BASE_ORDER + floorOffset + (gridPosition.y - gridPosition.x) * 10;
```
