# 任务剧情链路分析（截至 2026-05-12）

本文枚举了 **Quests / DialogueActions / OperationGuides / Conversations** 四类数据源的全部触发关系，给出"设计意图 → 当前实际"对照树，标出所有断点。

数据样本：
- 63 个 `QuestDefinition`（11 Main、52 Side）
- 11 个 `DialogueAction`（marker → 对话 / Lua 桥）
- 12 个 `OperationGuide`（marker → 引导面板，全部 `closingMarker = -1`，不产生新 marker）
- 32 个 conversation（Dialogue Database 中的剧本节点）

---

## 1. 触发模型（架构速览）

```
┌───────────────────────────────────────────────────────────────┐
│ C# 代码 raise marker (GameStateManager / DayLoopManager / etc.) │
└────────────┬──────────────────────────────────────────────────┘
             │
             ▼
   ┌────────────────────┐         ┌──────────────────────────┐
   │ TutorialEventBus   │────────►│ OperationGuideManager    │
   │ .OnMarkerTriggered │         │  (按 activationMarker 开面板)│
   └─────┬──────┬───────┘         └──────────────────────────┘
         │      │
         │      └──────────►┌──────────────────────────────────┐
         │                  │ TutorialMarkerBridge             │
         │                  │  按 activationMarker 跑 DialogueAction│
         │                  │  → 执行 Lua + StartConversation   │
         │                  └─────────────┬────────────────────┘
         │                                │
         ▼                                ▼
   ┌────────────────────┐      ┌────────────────────────────┐
   │ QuestLogicManager  │      │ Pixel Crushers Conversation │
   │  按 activationMarker│      │  对话中 userScript 调用 Lua │
   │  Activate(QuestN)  │◄─────│  SetQuestStateAfter / Raise │
   └─────────┬──────────┘      │  MarkerAfter (对话结束后执行)│
             │                 └────────────────────────────┘
             │ Quest 完成 → 触发 def.CompletionMarker
             └──────────────────────────► 回到 TutorialEventBus（递归）
```

**核心结论**：marker 既驱动「打开引导面板 / 启动对话」，也驱动「激活任务」。完成任务则反过来 raise 新 marker，形成链路。

## 7. 修复建议（按优先级）

### P0 - 修通主线推进
**问题**：Auditor/3-9 孤儿，导致 Main/4-9 + 所有数值大链 (Build/Income/Revenue/DailyCustomers) 死掉。

**两种方案**（取一）：

**方案 A：marker 驱动**（推荐，统一架构）
1. 在 `TutorialMarker` 新增 `Main1Completed`、`Main2Completed`、…、`Main8Completed`（追加到末尾）。
2. 给 `Main/1.completionMarker = Main1Completed`、`Main/2.completionMarker = Main2Completed` …
3. 新建 7 个 DialogueAction：`Marker MainNCompleted → StartConversation Auditor/{N+2}`。
4. 把 Auditor/3-9 末尾的 `SetQuestStateAfter("Main/N","active")` 流转保持不变。

**方案 B：对话链驱动**（改动小）
1. 在每个 Auditor/N（N=2..8）的末尾 dialogue entry 加 `outgoingLinks` 跨 conversation 跳转到 Auditor/(N+1) 的 root。
2. 在 Auditor/2 触发条件里也补一个跳到 Auditor/3 的 link，但要让前置 Main/2 完成才触发（用 conditionsString 限制）。

### P1 - 修通 VIP / BDSM 客人剧情线
**问题**：BDSM/1 + VIP/* 对话 8 个全孤儿。

设计上这些应该由 **特定 VIP 顾客进店触发**：
1. 在 `CustomerArchetypes/` 下为 BDSM 大哥、SoloFans 网红、ShyGirl 害羞女孩 创建独立 archetype。
2. 给它们的 `interactionEvents` 数组里挂一个 `InteractionEventSO` 引用对应的 `BDSM/1` / `VIP/SoloFans/N` conversation。
3. 或者用 `Day{N}Trigger` 来推（粗暴但快）：
   - `Day8Trigger → BDSM/1 conv`
   - `Day10Trigger → VIP/SoloFans/1 conv`
   - `Day12Trigger → VIP/ShyGirl/1 conv`
4. VIPSoloFans/{2,3,4} 应该接前一个 VIP 任务的 completionMarker（目前 4 个 VIP/SoloFans quest 的 `completionMarker = -1`，需要补）。
5. VIPShyGirl/{2,3} 同上。

### P2 - 三条独立断链
- **BP 链**：`BP10.activationMarker` 改为 `Day8Trigger`(35)（注释本来就这么写的）；或在某 NPC 对话里 `SetQuestStateAfter("Blueprints I","active")`。

- **Children's Day**：在 `CalendarManager` 监听 `Children's Day` 季节事件结束时 `TutorialEventBus.RaiseMarker(TutorialMarker.ChildrensDayFinished)`。

- `Sell1000.activationMarker`: 100 → 38 (Day15Trigger)
- 或者反过来——保留 VIP 误配，把 Serve/Sell 链头改成"Wellness 完成"或"Boost 完成"等更早的 marker，让它们在数值压力出现时就上线。
