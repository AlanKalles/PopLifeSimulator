# 顾客交互事件系统 (Customer Interaction Event System)

## 背景与目的

玩家之前有一个顾客交互系统（点击气泡触发对话），但改用 Pixel Crushers Dialogue System 后旧系统报废。需要基于新对话系统重新实现，同时用 ScriptableObject 数据驱动替代已移除的 Trait 依赖。

**核心玩法**：顾客在商店内到达货架队首后，有概率展示可交互 emoji 气泡。玩家在限定时间内点击顾客可触发对话（3 选 1 问答），答对获奖励，答错无奖励。超时未点击则顾客自动恢复正常购物。

**触发时机**：顾客在任何一次到达货架队首时都可能触发，不限于第一次购物。每人每天最多触发一次。

---

## 架构概览

```
InteractionEventData (SO)          ← 数据定义（过滤条件 + 对话 + 奖励）
    ↓
InteractionEventService (单例)     ← 全局事件池 + 实时掷骰匹配
    ↓
TryCustomerInteractionAction (BT)  ← 行为树节点（购物循环内，每次到货架时执行）
    ↓
CustomerDialogueTrigger (修改)     ← 点击路由到交互对话（优先于普通对话）
```

**触发流程**：顾客到达货架队首 → `TryCustomerInteractionAction` 执行 → 检查 `interactionUsedToday` → 调用 `InteractionEventService.TryRollInteraction(当前货架)` 掷骰 → 匹配事件池中符合当前货架的事件 → 展示气泡 → 等待点击/超时

### 1.1 `Scripts/Data/InteractionEventData.cs`

**命名空间**：`PopLife.Data`
**SO 资产路径**：`Resources/ScriptableObjects/InteractionEvents/`

```csharp
using System;
using UnityEngine;

namespace PopLife.Data
{
    [CreateAssetMenu(menuName = "PopLife/InteractionEvents/InteractionEventData")]
    public class InteractionEventData : ScriptableObject
    {
        [HideInInspector] public string eventId; // OnValidate 自动同步为文件名

        [Header("过滤条件")]
        [SerializeField] private bool useFilterCategory = false;
        [SerializeField] private ProductCategory requiredCategory;
        [SerializeField] private bool useFilterShelf = false;
        [SerializeField] private ShelfArchetype requiredShelf;

        [Header("对话配置")]
        [SerializeField] private string conversationTitle;

        [Header("奖励（回答正确时发放）")]
        [SerializeField] private QuestReward[] rewards;

        [Header("交互配置")]
        [SerializeField] private float bubbleTimeout = 10f;

        // 公共只读属性
        public string DisplayName => name;
        public bool UseFilterCategory => useFilterCategory;
        public ProductCategory RequiredCategory => requiredCategory;
        public bool UseFilterShelf => useFilterShelf;
        public ShelfArchetype RequiredShelf => requiredShelf;
        public string ConversationTitle => conversationTitle;
        public QuestReward[] Rewards => rewards;
        public float BubbleTimeout => bubbleTimeout;

#if UNITY_EDITOR
        private void OnValidate() { eventId = name; }
#endif
    }
}
```

**过滤规则**：
- 两个 filter 都为 false = 通用事件，任何货架都能触发
- `useFilterCategory = true` → 仅在匹配 `requiredCategory` 的货架触发
- `useFilterShelf = true` → 仅在匹配 `requiredShelf` 原型的货架触发
- 两个都为 true → 必须同时满足

### 1.2 `Scripts/Customers/Services/InteractionEventService.cs`

**命名空间**：`PopLife.Customers.Services`

```csharp
using System.Collections.Generic;
using UnityEngine;
using PopLife.Data;
using PopLife.Runtime;

namespace PopLife.Customers.Services
{
    public class InteractionEventService : MonoBehaviour
    {
        public static InteractionEventService Instance { get; private set; }

        [Header("交互事件配置")]
        [Range(0f, 1f)]
        [SerializeField] private float interactionProbability = 0.2f;

        [Header("调试")]
        [SerializeField] private int loadedEventCount = 0;

        private InteractionEventData[] allEvents;

        void Awake()
        {
            if (Instance != null && Instance != this) { Destroy(gameObject); return; }
            Instance = this;
            allEvents = Resources.LoadAll<InteractionEventData>("ScriptableObjects/InteractionEvents");
            loadedEventCount = allEvents?.Length ?? 0;
        }

        /// <summary>
        /// 在顾客到达货架队首后调用。掷骰概率 → 筛选匹配当前货架的事件 → 随机返回一个。
        /// 返回 null 表示本次不触发交互。
        /// </summary>
        public InteractionEventData TryRollInteraction(ShelfInstance currentShelf)
        {
            if (allEvents == null || allEvents.Length == 0) return null;
            if (currentShelf == null) return null;
            if (Random.value > interactionProbability) return null;

            var sa = currentShelf.archetype as ShelfArchetype;
            if (sa == null) return null;

            var eligible = new List<InteractionEventData>();
            foreach (var evt in allEvents)
            {
                if (DoesShelfMatchEvent(sa, evt))
                    eligible.Add(evt);
            }
            if (eligible.Count == 0) return null;
            return eligible[Random.Range(0, eligible.Count)];
        }

        private bool DoesShelfMatchEvent(ShelfArchetype sa, InteractionEventData evt)
        {
            if (!evt.UseFilterCategory && !evt.UseFilterShelf) return true;
            if (evt.UseFilterCategory && sa.category != evt.RequiredCategory) return false;
            if (evt.UseFilterShelf && sa != evt.RequiredShelf) return false;
            return true;
        }
    }
}
```

### 1.3 `Scripts/Customers/NodeCanvas/Actions/TryCustomerInteractionAction.cs`

**行为树 ActionTask，3 阶段状态机（无移动阶段，顾客已在货架）。**

```csharp
using NodeCanvas.Framework;
using ParadoxNotion.Design;
using UnityEngine;
using PixelCrushers.DialogueSystem;
using PopLife.Customers.Runtime;
using PopLife.Customers.Services;
using PopLife.Data;
using PopLife.Quest;
using PopLife.Runtime;
using PopLife.UI;

namespace PopLife.Customers.NodeCanvas.Actions
{
    [Category("PopLife/Customer")]
    [Description("顾客交互事件：在货架前掷骰 → 播放交互动画 → 等待玩家点击 → 对话 → 发放奖励")]
    public class TryCustomerInteractionAction : ActionTask
    {
        private enum Phase { WaitForClick, WaitForDialogue, HandleResult }

        [UnityEngine.Header("黑板绑定")]
        public BBParameter<string> targetShelfId;

        private Phase currentPhase;
        private CustomerBlackboardAdapter adapter;
        private CustomerAnimationController animController;
        private InteractionEventData currentEvent;
        private float phaseTimer;

        protected override string info => "Try Customer Interaction";

        protected override void OnExecute()
        {
            adapter = agent.GetComponent<CustomerBlackboardAdapter>();
            // 今日已触发过 → 立即通过
            if (adapter == null || adapter.interactionUsedToday) { EndAction(true); return; }

            // 查找当前货架
            var shelf = FindShelfById(targetShelfId.value);
            if (shelf == null) { EndAction(true); return; }

            // 掷骰 + 匹配事件
            var rolledEvent = InteractionEventService.Instance?.TryRollInteraction(shelf);
            if (rolledEvent == null) { EndAction(true); return; }

            currentEvent = rolledEvent;
            adapter.assignedInteraction = rolledEvent;

            animController = agent.GetComponent<CustomerAnimationController>();
            if (animController == null) { adapter.assignedInteraction = null; EndAction(true); return; }

            // 进入 WaitForClick
            currentPhase = Phase.WaitForClick;
            phaseTimer = 0f;
            adapter.interactionBubbleActive = true;
            animController.PlayInteraction();
        }

        // ... WaitForClick / WaitForDialogue / HandleResult / CleanupAndEnd / OnStop
        // 逻辑同旧版，但移除了所有 AILerp/MoveToShelf 相关代码
    }
}
```

**关键变更（vs 旧版）**：
- 删除 `Phase.MoveToShelf` 及 `UpdateMoveToShelf()`（顾客已在货架队首）
- 删除 `aiLerp`, `targetShelf`, `stoppingDistance`, `moveTimeout` 等移动相关字段
- 新增 `BBParameter<string> targetShelfId`（绑定黑板，同 ExecutePurchaseAction 模式）
- `OnExecute()` 中实时掷骰：`InteractionEventService.TryRollInteraction(shelf)`
- `OnStop()` 不再需要停止 AILerp

## 三、行为树修改（手动 Unity Editor）

### 新结构

```
StepIterator
  ├─ MoveToEntranceAction
  ├─ [Favorite Phase Repeater]
  │   ├─ SelectTargetShelfAction
  │   ├─ MoveToTargetAction
  │   ├─ AcquireQueueSlotAction
  │   ├─ IsAtFrontOfQueueCondition
  │   ├─ TryCustomerInteractionAction   ← 新位置（队首 → 购买前）
  │   ├─ DecidePurchaseAction
  │   ├─ ExecutePurchaseAction
  │   ├─ ReleaseQueueSlotAction
  │   └─ ThinkBeforeNextShoppingAction
  ├─ [Category Phase] (同样插入)
  ├─ [Brand Phase] (同样插入)
  └─ [PriceBased Phase] (同样插入)
  └─ Leave Strategy
```

### 操作步骤

1. 删除 StepIterator 下原有的 `TryCustomerInteractionAction` 节点（MoveToEntrance 之后的位置）
2. 在 4 个 Phase Repeater 中，各插入一个 `TryCustomerInteractionAction` 节点：
   - 放在 `IsAtFrontOfQueueCondition` 之后、`DecidePurchaseAction` 之前
3. 绑定每个节点的 `targetShelfId` BBParameter 到黑板的 `targetShelfId` 变量
4. 节点始终返回 `EndAction(true)`，不影响 Sequencer 后续步骤

## 四、Dialogue Database 设置（手动 Pixel Crushers Dialogue Editor）

每个交互事件需要一个对话 Conversation：

```
Conversation: "Interaction/Vibrator_Question"（与 SO 的 conversationTitle 一致）
│
├─ NPC Node: "What type of vibrator would you recommend for a beginner?"
│
├─ Player Response 1: "A bullet vibrator - simple and discreet" ← 正确
│   └─ Script: Variable["InteractionCorrect"] = true
│   └─ NPC Node: "Great advice! That's exactly what I was thinking."
│
├─ Player Response 2: "The biggest one we have" ← 错误
│   └─ NPC Node: "Hmm, I'm not sure about that..."
│
└─ Player Response 3: "I don't know much about those" ← 错误
    └─ NPC Node: "Oh well, I'll figure it out myself."
```

- 正确选项设置 `Variable["InteractionCorrect"] = true`
- 错误选项不设置（代码初始化为 false）
- ESC 关闭对话 → false → 无奖励但不卡死

## 五、完整数据流

```
[生成阶段]
CustomerSpawner.SpawnCustomer()
  └─ 重置交互状态（防御性：对象池脏数据清理）
       └─ assignedInteraction = null, interactionUsedToday = false, etc.
  └─ （不再在此分配交互事件）

[购物循环 - 每次到达货架]
Phase Repeater
  └─ SelectTargetShelf → MoveToTarget → AcquireQueue → IsAtFrontOfQueue

  └─ TryCustomerInteractionAction
       ├─ interactionUsedToday == true → EndAction(true) 跳过
       ├─ FindShelfById(targetShelfId) 找到当前货架
       ├─ InteractionEventService.TryRollInteraction(shelf)
       │    ├─ Random.value > 0.2 → 返回 null（80% 不触发）
       │    ├─ 遍历所有 InteractionEventData SO
       │    │    └─ DoesShelfMatchEvent(): 检查当前货架是否匹配事件过滤条件
       │    └─ 有匹配 → 随机选一个返回
       ├─ 结果为 null → EndAction(true) 跳过
       ├─ 设置 adapter.assignedInteraction + interactionBubbleActive
       ├─ PlayInteraction() 显示 emoji 气泡
       │
       ├─ Phase.WaitForClick:
       │    ├─ 检查 adapter.interactionDialogueStarted
       │    │    → true: StopLoop()，进入 WaitForDialogue
       │    └─ 超时: phaseTimer >= bubbleTimeout → CleanupAndEnd()
       │
       ├─ Phase.WaitForDialogue:
       │    └─ 等 !DialogueManager.isConversationActive → 进入 HandleResult
       │
       └─ Phase.HandleResult:
            ├─ 读 DialogueLua["InteractionCorrect"]
            ├─ true → DistributeSingleReward() + FloatingText + AudioManager
            └─ CleanupAndEnd()（设置 interactionUsedToday = true）

  └─ DecidePurchase → ExecutePurchase → ReleaseQueue → Think

[点击路径]
PlayerClick → CustomerDialogueTrigger.TryTriggerDialogue()
  → 检查 adapter.interactionBubbleActive == true
  → 启动交互对话，设置 interactionDialogueStarted = true

[中断路径]
OnStop() → 清理动画/标志位，不标记 interactionUsedToday
```

## 六、关键设计决策

| 决策 | 选择 | 原因 |
|------|------|------|
| 触发时机 | 每次到达货架队首时掷骰 | 不限于第一次购物，增加玩家互动机会 |
| 每日限制 | `interactionUsedToday` 标志 | 每人每天最多 1 次，避免过度打断 |
| 事件匹配 | 当前货架 vs 事件过滤条件 | 仅在匹配的货架触发，符合事件上下文 |
| 无移动阶段 | 顾客已在货架队首 | 行为树节点在 IsAtFrontOfQueue 之后执行 |
| 数据定义 | ScriptableObject | 符合项目数据驱动设计风格 |
| 对话系统 | Pixel Crushers Dialogue System | 已有完整基础设施 |
| 奖励判定 | Lua 变量 `InteractionCorrect` | 对话内容与代码逻辑解耦 |

## 七、OnStop() 与 CleanupAndEnd() 职责分离

```
CleanupAndEnd()                          OnStop()
───────────────────────────              ───────────────────────────
正常完成（点击对话/超时）                 外部中断（商店关门/顾客愤怒）

✅ 清理动画/标志位                       ✅ 清理动画/标志位
✅ interactionUsedToday = true            ❌ 不设 interactionUsedToday
✅ EndAction(true)                        ❌ 不调用 EndAction（NodeCanvas 自动处理）
```

## 八、验证方案

1. **编译测试**：Unity 编译无报错
2. **单次触发测试**：顾客在某个货架展示气泡 → 点击 → 对话 → 奖励 → 后续货架不再触发
3. **跨阶段测试**：如果 Favorite 阶段未触发，Category/Brand/PriceBased 阶段仍有机会触发
4. **过滤测试**：带 category 过滤的事件仅在匹配品类的货架触发
5. **超时测试**：不点击气泡 → 超时消失 → 顾客正常购买 → 后续不再触发
6. **中断测试**：交互期间商店关门 → OnStop() 清理正确，emoji 消失
7. **ESC 关闭对话测试**：交互对话弹出后按 ESC → 无奖励但不卡死
8. **概率测试**：大多数货架访问不触发（80%跳过），观察 Debug.Log 确认
