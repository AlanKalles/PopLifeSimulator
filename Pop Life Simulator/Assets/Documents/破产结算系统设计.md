# 破产结算系统设计

## 设计目标

替换原本"金钱负数即 Game Over"的硬性破产逻辑，让破产成为**多阶段宽容机制**——玩家有预警、有补救、有渐进难度递增，最后才走 Game Over。

## 玩家流程

### 1. 预警（实时 UI）
- **当前预计维护费**：`Maintenance: $80/day` — 实时显示，随建造/拆除/升级/Buffer 变动
- **当日销售额**：`Today's Sales: $450` — BuildPhase 为 0，OpenPhase 实时累加，下一天重置
- **金钱负数**：UI 显示 `-$200`，红色字体

### 2. 负债（允许）
- 玩家**仅**可因维护费导致负债（建造系统已通过 `CanAfford` 阻止建造负债）
- 负债期间：
  - **可以**：开店、补货、营业（赚钱还债的途径）
  - **不可以**：建造任何新建筑（弹"NOT ENOUGH MONEY"提示）

### 3. 首次负债 — 教学
- **触发条件**：玩家整个存档第一次出现 `money < 0`
- **效果**：触发 `Midori/Bankrupt/1` 对话，Midori 提醒玩家：
  - 货架有维护费要时刻注意
  - 根据顾客喜好与品牌选择合适的货架
  - 可以负债一天，第二天结束前还清就 OK
- 仅触发**一次**（lifetime），之后再次进入负债不再弹此对话

### 4. 还债失败 — 三阶补助
- **判定**：上次结算后处于负债态（`debtWarningActive == true`），这次扣完维护费仍负债
- **响应**（按累计失败次数递进）：

| 累计失败次数 | 对话 | 补助金额（默认） |
|---|---|---|
| 1 | `Midori/Bankrupt/2` | $100 |
| 2 | `Midori/Bankrupt/3` | $300 |
| 3 | `Midori/Bankrupt/4` | $500 |
| 4+ | （无） | 真正破产 → Game Over |

补助金额可在 `BankruptcyManager` 组件 Inspector 中调整。

### 5. Game Over
- **触发**：`debtFailureCount >= gameOverFailureCount`（默认 4）
- **效果**：跳过结算面板，直接显示 BankruptcyPanel（Restart / Quit 按钮）
- 不发补助、不更新 `debtWarningActive`

## 数据持久化

ES3 keys（`SaveFile.es3` 中）：

| Key | 类型 | 含义 |
|---|---|---|
| `BankruptcyMgr_HasFirstDebtTriggered` | bool | 首次负债对话是否已触发（lifetime 一次） |
| `BankruptcyMgr_DebtFailureCount` | int | 还债失败累计次数（lifetime，永不重置） |
| `BankruptcyMgr_DebtWarningActive` | bool | 上次结算后玩家是否仍负债（在所有处理含补助到账后用最终金额判定） |

`GameStateManager.ClearAllSaves` 中已接入这 3 个 key + `BankruptcyManager.ClearSaveAndResetState()` 兜底。

## 时序图

```
关店时间到达
  ↓
TriggerStoreClose:
  - isStoreOpen = false
  - OnStopSpawning 触发（CustomerSpawner 停止生成）
  - 启动 WaitForCustomersToLeave
  ↓
等所有顾客离开商店（最多 30s 超时）
  ↓
OnStoreClose 触发（唯一触发点 — UI 状态刷新）
  ↓
[1] 彩票开奖（如果玩家本期买票）
  ↓
[2] 扣除维护费（基础值 × GlobalModifier 维护乘数）
  ↓
[3] BankruptcyManager.EvaluatePostMaintenance:
    if (debtWarningActive && money < 0):
        debtFailureCount++
        if (count >= 4): result.gameOver = true → return
        else: 播放 Midori/Bankrupt/2|3|4 → 补助到账
    elif (money < 0 && !hasFirstDebtTriggered):
        hasFirstDebtTriggered = true → 播放 Midori/Bankrupt/1
    
    debtWarningActive = (最终金额 < 0)  ← 关键：补助后用最终金额判定
    SaveToES3()
  ↓
if (gameOver):
  OnBankruptcy → 显示 BankruptcyPanel → PauseTime
else:
  ShowSettlementUI(maintenance, sponsorship) → 显示结算面板
```

## 关键设计决策

### 1. `debtWarningActive` 的判定时机
**在所有处理（包含补助到账）之后**用最终金额更新：
```csharp
debtWarningActive = ResourceManager.Instance.GetMoney() < 0;
```
原因：如果在补助前判定，补助让钱回正后下一天仍会被误判为"还在债中"，导致连续误触发还债失败 +1。

### 2. 维护费扣除时机
原本在 `CalculateDailySettlement` 内扣费（结算面板**显示后**才扣）→ 玩家无机会反应。
现在抽离为 `CalculateAndDeductMaintenance`，在结算面板显示**之前**扣，给 `BankruptcyManager` 判定空间。

### 3. 删除 OpenStore / AdvanceToNextDay 的破产早 return
原本玩家结算后负债时会被 `OpenStore` / `AdvanceToNextDay` 中的 `CheckBankruptcy` 拦下 → 无法营业还债 → 死锁。
现在破产判定唯一发生在 `BankruptcyManager.EvaluatePostMaintenance`（结算面板之前），允许负债玩家进入下一天继续营业。

### 4. RestockPanel 允许负债时补货
补货是营业必需 — 禁止则负债玩家死锁（无库存无法营业，无法营业无法还债）。
风险由"4 次还债失败 = Game Over"机制兜底。

### 5. 对话流程的协程暂停
`BankruptcyManager.PlayConversation` 用最简化 pause→start→wait→resume 流程，**不承诺** StopCoroutine 中断时一定 Resume（协程的固有限制）。如果未来需要更强保证，应迁移到 `DialogueGameplayPauseService.PushExternalPause/PopExternalPause` 模式。

## 扩展点

### 调整补助梯度
直接在 BankruptcyManager Inspector 中改三个 SerializeField 即可。

### 增加补助阶段（如 4/5/6 次失败也给补助）
1. 添加 `[SerializeField] private int fourthFailureSponsorship = 700;` 等字段
2. 添加对应 conversation 字段
3. 修改 `GetSponsorshipForFailure` 与 `GetFailureConversation` switch 表达式
4. 提高 `gameOverFailureCount` 默认值

### 减少首次负债的频率（教学性）
当前 `hasFirstDebtTriggered` 永久 lifetime 一次。如果想"每次重新负债都提示"，把 `hasFirstDebtTriggered` 在还债成功（钱回正）时重置为 false。

## 修复的现存 Bug

### Bug A — 第三天结算 Continue 后卡死
**根因**：场景中 `Bankrupt` GameObject `m_IsActive: 0` → BankruptcyPanel 永远不订阅 OnBankruptcy → 维护费扣完 money 负数 → AdvanceToNextDay 触发 OnBankruptcy（无订阅者）+ PauseTime → 卡死。

**修复**：
1. 删除 `OpenStore` / `AdvanceToNextDay` 中的 CheckBankruptcy 早 return
2. 破产判定移至 `BankruptcyManager.EvaluatePostMaintenance`（结算面板之前）
3. BankruptcyPanel 加 `panelRoot == gameObject` 配置错误警告
4. 场景重构：`Bankrupt` 父节点保持 active，子节点 `BankruptVisual` 作为 panelRoot（需 Unity Editor 操作）

### Bug B — OnStoreClose 双重触发
**根因**：`TriggerStoreClose` 关店开始时触发一次，`WaitForCustomersToLeave` 顾客离开后又触发一次。订阅方（TimeControlUI / PhaseLockedButton / GameStateLuaSync）都是 UI 状态刷新，应只在"商店真正关闭"那一刻触发。

**修复**：删除 `TriggerStoreClose` 中的第一次 `OnStoreClose?.Invoke()`，保留 `WaitForCustomersToLeave` 末尾的唯一触发。`CustomerSpawner` 实际订阅 `OnStopSpawning`，不受影响。

## 场景配置清单

代码改动后需要在 Unity Editor 完成以下配置：

### 必做（核心功能）
1. **挂载 `BankruptcyManager`**：在场景的 Manager 容器 GameObject 上添加 `BankruptcyManager` 组件
2. **修复 `Bankrupt` 场景层级**（方案 A）：
   - 选中 `Bankrupt` GameObject，Inspector 勾选 active
   - 创建子节点 `BankruptVisual`，把 messageText / debtText / restartButton / quitButton 及背景图整体移到 `BankruptVisual` 下
   - 子节点初始 inactive
   - `BankruptcyPanel.panelRoot` 字段重新指向 `BankruptVisual`

### 推荐（预警 UI）
3. **ResourceDisplay 扩展字段**：在 Inspector 中拖拽：
   - `maintenanceFeeText`（新增 TextMeshProUGUI）
   - `todayIncomeText`（新增 TextMeshProUGUI）

### 可选（视觉打磨）
4. **NewDailySettlementPanel Extra Income 区域**：
   - 创建 `extraIncomeSection` 容器（含 header）
   - 创建 `extraIncomeContainer`（VerticalLayoutGroup）
   - 创建 `extraIncomeItemPrefab`（含 ExtraIncomeItem 组件 + 2 个 TextMeshProUGUI 子节点）
   - 在 NewDailySettlementPanel Inspector 中拖拽这 3 个引用

5. **Midori/Bankrupt/1-4 对话**：在 Pixel Crushers Dialogue Editor 中创建 4 条对话（剧本由设计师编写）

如果跳过 1：玩家不破产前一切正常，破产相关静默失效（无对话、无补助、无 game over，但不会卡死）。
如果跳过 2：真破产时仍卡死（原 Bug A 残留）。
如果跳过 3：玩家看不到预警，但其他正常。
如果跳过 4：彩票/补助词条不显示（功能不影响）。
如果跳过 5：相关时机仅 console 警告 `Conversation not found`，流程继续。
