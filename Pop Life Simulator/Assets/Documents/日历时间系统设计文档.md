# 日历与时间系统设计文档

## 概述

日历与时间系统为游戏引入年/季节/日的时间结构，并在 AlanBot 面板中提供可视化日历 UI。玩家可以浏览不同季节、查看季节事件（SeasonEvent）、活跃 Buffer、以及任务截止日期（Due Date）。

**作用域分层**：CalendarManager 负责时间结构、事件/Buffer 生命周期与视觉展示；GlobalModifierManager 负责聚合所有活跃事件/Buffer 的修饰效果并提供 O(1) 只读查询，涵盖经济修正、AI行为修饰等多维度影响。两个系统通过 `OnCalendarDataChanged` 事件单向耦合。

## 第一部分：核心时间系统

### CalendarUtils（静态工具类）

**文件**: `Scripts/Data/CalendarUtils.cs`
**命名空间**: `PopLife.Data`

```
1 年 = 4 季节 × 12 天 = 48 天
Season 枚举: Spring(0), Summer(1), Autumn(2), Winter(3)
absoluteDay: 从 1 开始（1-based）
```

#### 关键常量

| 常量 | 值 | 说明 |
|------|-----|------|
| `DaysPerSeason` | 12 | 每季节天数 |
| `SeasonsPerYear` | 4 | 每年季节数 |
| `DaysPerYear` | 48 | 每年总天数 |

#### API

| 方法 | 说明 |
|------|------|
| `AbsoluteDayToDate(int absoluteDay, int startingYear)` | absoluteDay → GameDate |
| `DateToAbsoluteDay(int year, Season, int dayInSeason, int startingYear)` | GameDate → absoluteDay |
| `GetSeasonStartDay(int absoluteDay)` | 返回所在季节第一天的 absoluteDay |
| `GetSeasonRange(int absoluteDay)` | 返回所在季节的 [start, end] 范围（inclusive） |
| `GetSeasonDisplayName(Season)` | 枚举转英文大写显示名 |

#### 取余数学安全写法

**陷阱**：直接 `absoluteDay % 12` 会导致第 12 天算出 0。

**安全写法**：先转 0-based 再运算：
```csharp
int zeroIndexed = absoluteDay - 1;           // 转为 0-based
int dayInSeason = (zeroIndexed % 12) + 1;    // +1 回到 1-based
```

#### 边界验证

| absoluteDay | 预期结果 |
|-------------|---------|
| 1 | Year 2126, Spring, Day 1 |
| 12 | Year 2126, Spring, Day 12 |
| 13 | Year 2126, Summer, Day 1 |
| 48 | Year 2126, Winter, Day 12 |
| 49 | Year 2127, Spring, Day 1 |

```csharp

}
```

## 第三部分：CalendarManager — 生命周期管理

**文件**: `Scripts/Manager/CalendarManager.cs`
**命名空间**: `PopLife`
**执行顺序**: `[DefaultExecutionOrder(-50)]`（DayLoopManager 为 -100）

### 单例

```csharp
CalendarManager.Instance
```

需挂载到场景中的 Manager GameObject 上。

### 数据加载

```csharp
// Awake 中从 Resources 自动加载（Inspector 未赋值时）
allSeasonEvents = Resources.LoadAll<SeasonEventData>("ScriptableObjects/Calendar/SeasonEvents");
allBuffers = Resources.LoadAll<BufferData>("ScriptableObjects/Calendar/Buffers");
```

也可在 Inspector 中手动拖入。

### 每日生命周期

订阅 `DayLoopManager.OnBuildPhaseStart`，每天建造阶段开始时执行：

```
OnNewDayStart():
1. RefreshTodaySeasonEvents(date)
   - 遍历所有 SeasonEventData SO
   - 匹配条件: season 相同 && dayInSeason 在 [start, start+duration-1] 范围内

2. TickActiveBuffers()
   - remainingDays > 0 → 递减，到 0 移除，触发 OnBufferEnded
   - remainingDays < 0（无限期）→ 检查 terminateProbability，命中则移除

3. RollAutoBuffers(today)
   - 遍历所有 triggerType == Auto 的 BufferData
   - 跳过已激活的同 bufferId（不叠加）
   - 检查 occurProbability，命中则激活

4. SaveBufferState()    ← ES3 持久化
5. OnCalendarDataChanged?.Invoke()   ← 通知 UI 刷新
```

### 手动 Buffer 触发

```csharp
public bool TryActivateManualBuffer(BufferData bufData)
```

流程：
1. 检查 `triggerType == Manual`
2. 检查该 bufferId 是否已激活（不叠加）
3. 检查 `ResourceManager.Instance.CanAfford(bufData.hostCost, 0)`
4. 扣费 → 激活 Buffer → 保存 → 广播

### 公共查询 API

| 方法 | 说明 |
|------|------|
| `GetEventsForDay(int absoluteDay)` | 指定日的季节事件（每年重复） |
| `GetBuffersForDay(int absoluteDay)` | 指定日活跃的 Buffer（按 start+duration 判断） |
| `GetActiveBuffers()` | 当前所有活跃 Buffer 副本 |
| `GetTodaySeasonEvents()` | 今日活跃的季节事件副本 |
| `GetAllSeasonEvents()` | 所有季节事件 SO 数组 |
| `GetAllBufferDefinitions()` | 所有 Buffer SO 数组 |

### 事件

| 事件 | 说明 |
|------|------|
| `OnCalendarDataChanged` | Buffer 状态变化时广播（UI 刷新用） |
| `OnBufferStarted(BufferData)` | Buffer 激活时 |
| `OnBufferEnded(BufferData)` | Buffer 结束时 |

### Buffer 在日历上的显示范围

- **固定时长 Buffer**: 在 `[startAbsoluteDay, startAbsoluteDay + durationDays - 1]` 每一天都显示
- **无限期 Buffer**: 从 `startAbsoluteDay` 到当前季节末尾显示（避免无限延伸）

### ES3 持久化

| 键名 | 数据类型 | 说明 |
|------|---------|------|
| `CalendarActiveBuffers` | `List<ActiveBuffer>` | 活跃 Buffer 列表 |

加载时通过 `bufferId` 从 `allBuffers` 重建 `data` (SO) 引用。找不到 SO 的记录自动移除。

#### 核心逻辑

**Show(Action closeCallback)**
1. 保存关闭回调
2. 初始化网格（仅首次，创建 12 个 DayBlock 实例）
3. 定位到当前季节（`GetSeasonStartDay(currentDay)`）
4. 刷新显示
5. 淡入

**RefreshDisplay()**
1. 更新 Header（季节名、图标、年份）
2. 预取 Due Date 数据（`QuestDataService.GetActiveQuestDeadlines()`）
3. 对每个格子 i = 0..11：
   - `absoluteDay = viewingSeasonStartDay + i`
   - 查询季节事件 → `CalendarManager.GetEventsForDay(absoluteDay)`
   - 查询活跃 Buffer → `CalendarManager.GetBuffersForDay(absoluteDay)`
   - 筛选 Due Date → 匹配 `dueAbsoluteDay == absoluteDay`
   - 合并为 `List<CalendarEventEntry>` → `dayBlock.Setup()`

**导航**
- `OnPrevSeason()`: `viewingSeasonStartDay -= 12`，不低于 1
- `OnNextSeason()`: `viewingSeasonStartDay += 12`，无上限
- `OnToday()`: 回到当前天所在季节

## 第五部分：UI 路由 — Calendar → QuestLog → AlanBot

### 路由链完整流程

```
AlanBot.OnCalendarClicked()
  → 保存 AlanBot 回调，隐藏 AlanBot
  → Calendar.Show(closeCallback: () => AlanBot.Show(savedCallback))

【正常关闭：X / Esc】
  → Calendar.Hide() → 触发 closeCallback → AlanBot 重新显示 ✓

【Due Date 点击】
  → Calendar 保存 closeCallback 为 originalCB
  → Calendar.HideWithoutCallback()（纯淡出，不触发回调）
  → QuestLog.Show(questName, closeCallback: () => originalCB())

【QuestLog 关闭：X / Esc / P】
  → QuestLog.Hide() → FadeOut() → 触发 closeCallback
  → originalCB() → AlanBot.Show(savedCallback) ✓
```

### AlanBotSelectionPanel 修复

`OnCalendarClicked()` 现在遵循与 ItemCodex / CustomerCodex 一致的回调保存模式：

```csharp
private void OnCalendarClicked()
{
    var savedCallback = onHideCallback;
    onHideCallback = null;
    Hide();
    if (calendarPanel != null)
        calendarPanel.Show(closeCallback: () => { Show(savedCallback); });
}
```

### CalendarPanel 的 Due Date 路由

```csharp
private void OnDueDateClicked(CalendarEventEntry entry)
{
    if (string.IsNullOrEmpty(entry.questName)) return;

    // 1. 保存原始关闭回调
    var originalCloseCallback = onCloseCallback;
    onCloseCallback = null;  // 防止 Hide 触发它

    // 2. 纯淡出，不触发任何回调
    HideWithoutCallback();

    // 3. 打开 QuestLogPanel
```

## 第九部分：全局修饰器系统（GlobalModifierSystem）

### 概述

GlobalModifierSystem 是日历系统的经济与行为影响层。CalendarManager 管理事件/Buffer 的**生命周期**（何时激活、何时终止），GlobalModifierManager 负责将所有活跃效果**聚合烘焙**为单一缓存并暴露 O(1) 只读查询。

两者通过 `CalendarManager.OnCalendarDataChanged` 单向耦合：CalendarManager 不知道修饰器的存在，GlobalModifierManager 不参与事件/Buffer 的生命周期管理。

### 架构约束（设计红线）

| 编号 | 约束 | 说明 |
|------|------|------|
| A | **不碰基础值** | 活跃修饰器永远不覆盖任何实体的原始变量。最终值 = 基础值 × Getter() |
| B | **加性百分比叠加** | 同一修饰器字段多 Buff 叠加：`total = 1.0 + Σ(buff_i - 1.0)`，防止乘法爆炸 |
| C | **兴趣并集** | 奖励兴趣品类与核心兴趣取 Union（HashSet 自动去重），不覆盖 |
| D | **不序列化聚合结果** | 仅 CalendarManager 持久化 Buffer ID + 剩余天数。加载时从 SO 重建 MasterPayload |
| E | **O(1) 读取** | 品类乘数使用 `float[ProductCategory.Length]` 平铺数组，枚举整数直接寻址 |

### 文件结构

| 文件 | 命名空间 | 说明 |
|------|----------|------|
| `Scripts/Data/GlobalModifierPayload.cs` | `PopLife.Data` | Inspector 可编辑的修饰器数据载荷 |
| `Scripts/Manager/GlobalModifierManager.cs` | `PopLife` | 聚合管理器单例 `[DefaultExecutionOrder(-40)]` |

### 数据结构

#### GlobalModifierPayload（设计师填写，Inspector序列化）

```
[Serializable] class GlobalModifierPayload:

  A. 全局乘数（默认1.0，无影响）
  ├── constructionCostMultiplier     建造成本（Money）
  ├── upgradeCostMultiplier          升级成本（Fame）
  ├── customerSpawnRateMultiplier    顾客生成速率（>1=更快）
  ├── customerMoneyBagMultiplier     顾客钱包容量
  └── globalFameGainMultiplier       全局Fame获取

  B. 品类定向乘数（Inspector用List，运行时扁平化为float[]）
  ├── List<CategoryModifier> categoryPriceModifiers      品类售价
  ├── List<CategoryModifier> categoryFameModifiers       品类Fame
  └── List<CategoryModifier> categoryQuantityModifiers   品类购买数量

  C. 货架Appeal加值（平坦整数）
  └── List<ShelfAppealModifier> shelfAppealModifiers
      ├── targetShelf = null → 全局生效
      └── targetShelf = 具体SO → 仅该货架

  D. AI行为修饰
  └── List<ProductCategory> bonusInterestCategories
      顾客生成时临时加入购物偏好（Union合并）
```

#### 辅助结构体

```csharp
[Serializable] struct CategoryModifier
{
    ProductCategory category;
    float multiplier;          // 1.0=无影响, 1.3=+30%, 0.8=-20%
}

[Serializable] struct ShelfAppealModifier
{
    ShelfArchetype targetShelf;  // null=全局
    int addend;                  // 平坦加值
}
```

#### MasterPayload（运行时缓存，不序列化）

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `constructionCostMul` | float | 1.0 | 建造成本总乘数 |
| `upgradeCostMul` | float | 1.0 | 升级成本总乘数 |
| `spawnRateMul` | float | 1.0 | 生成速率总乘数 |
| `moneyBagMul` | float | 1.0 | 钱包容量总乘数 |
| `globalFameMul` | float | 1.0 | 全局Fame总乘数 |
| `categoryPriceMul[11]` | float[] | 全1.0 | 品类售价乘数（枚举索引） |
| `categoryFameMul[11]` | float[] | 全1.0 | 品类Fame乘数（枚举索引） |
| `categoryQuantityMul[11]` | float[] | 全1.0 | 品类购买量乘数（枚举索引） |
| `globalAppealAddend` | int | 0 | 全局Appeal加值 |
| `shelfSpecificAppealAddends` | Dict\<ShelfArchetype,int\> | 空 | 货架特定Appeal加值 |
| `bonusInterests` | HashSet\<ProductCategory\> | 空 | 奖励兴趣品类集合 |

### 聚合引擎

```
CalendarManager.OnCalendarDataChanged
        │
        ▼
GlobalModifierManager.RebakePayload()
  1. ResetPayload()          ← 所有乘数归1，加值归0，集合清空
  2. foreach 今日季节事件:
       AggregatePayload(event.modifierPayload)
  3. foreach 活跃Buffer:
       AggregatePayload(buffer.data.modifierPayload)
  4. 缓存完成，消费端即刻可读
```

#### AggregatePayload 叠加规则

```
对每个全局乘数字段:
  total += (payload.value - 1.0)
  示例: BuffA=1.5(+50%), BuffB=1.2(+20%) → total = 1.0 + 0.5 + 0.2 = 1.7

对品类乘数:
  categoryXxxMul[(int)cat] += (modifier.multiplier - 1.0)
  仅影响指定品类，其余保持1.0

对Appeal加值:
  targetShelf == null → globalAppealAddend += addend
  targetShelf != null → shelfSpecificAppealAddends[arch] += addend
  (使用TryGetValue安全处理不存在的key)

对奖励兴趣:
  bonusInterests.Add(cat)   ← HashSet自动去重
```

### 只读 Getter API

| 方法 | 返回值 | 下限保护 | 消费端 |
|------|--------|----------|--------|
| `GetConstructionCostMultiplier()` | float | Max(0) | FloorGrid, ConstructionManager |
| `GetUpgradeCostMultiplier()` | float | Max(0) | BuildingInstance, BuildingDetailPanel |
| `GetSpawnRateMultiplier()` | float | Max(0) | CustomerSpawner |
| `GetMoneyBagMultiplier()` | float | Max(0) | CustomerAgent |
| `GetGlobalFameMultiplier()` | float | 允许负数 | CustomerInteraction |
| `GetCategoryPriceMultiplier(cat)` | float | Max(0) | ShelfInstance |
| `GetCategoryFameMultiplier(cat)` | float | 允许负数 | CustomerInteraction |
| `GetCategoryQuantityMultiplier(cat)` | float | Max(0) | RandomPurchasePolicy |
| `GetFameMultiplier(cat)` | float | 允许负数 | CustomerInteraction |
| `GetShelfAppealAddend(arch)` | int | 无限制 | ShelfInstance |
| `GetBonusInterestCategories()` | HashSet | — | CustomerAgent |

> **下限保护说明**：成本、速率、数量类乘数用 `Mathf.Max(0f, ...)` 保护，防止负数导致倒扣。Fame 允许负数以支持惩罚性事件。

### 集成点（7处注入）

#### 1. 建造成本 — FloorGrid + ConstructionManager

```
原始: arch.buildCost
修正: Mathf.RoundToInt(arch.buildCost × GetConstructionCostMultiplier())
影响: CanAfford检查、SpendMoney扣费、回滚退款、浮动文字显示
```

#### 2. 升级成本 — BuildingInstance + BuildingDetailPanel

```
原始: next.upgradeFameCost
修正: Mathf.RoundToInt(next.upgradeFameCost × GetUpgradeCostMultiplier())
影响: TryUpgrade逻辑、面板显示、按钮可用状态（4处UI引用）
```

#### 3. 顾客生成间隔 — CustomerSpawner

```
原始: finalInterval = (baseInterval + jitter) × intervalMul
修正: finalInterval = ... / Max(0.01, GetSpawnRateMultiplier())
语义: spawnRate > 1 → 间隔缩短 → 顾客更频繁（反比关系）
```

#### 4. 顾客钱包 + 奖励兴趣 — CustomerAgent

```
钱包:
  原始: walletCap = walletCapBase × curve(loyalty)
  修正: walletCap = ... × GetMoneyBagMultiplier()

兴趣:
  原始: categories = 从 favoriteShelfIds 解析
  修正: categories ∪= GetBonusInterestCategories()
  注入时机: 在复制到 bb.favoriteCategoryIndices 之前
  去重: HashSet<int> 天然防重复
```

#### 5. Fame计算 — CustomerInteraction

```
原始: fameGained = FameCalculator.CalculateFame(price, appeal)
修正: fameGained *= GetFameMultiplier(category)
     = GetGlobalFameMultiplier() × GetCategoryFameMultiplier(category)
语义: 全局Fame层 × 品类Fame层，两层独立聚合后相乘
```

#### 6. 货架Appeal + 有效售价 — ShelfInstance

```
Appeal:
  原始: return lv.appeal × catMul
  修正: return (lv.appeal × catMul) + GetShelfAppealAddend(archetype)

售价 (新增 GetEffectivePrice 方法):
  原始: currentPrice（基础值，不修改）
  修正: Max(1, RoundToInt(currentPrice × GetCategoryPriceMultiplier(cat)))
  消费端: CustomerInteraction 全部改用 GetEffectivePrice()
```

#### 7. 购买数量 — RandomPurchasePolicy

```
原始: finalQty = Min(RoundToInt(adjustedQty), budgetLimit, stock)
修正: finalQty = Min(RoundToInt(adjustedQty × GetCategoryQuantityMultiplier(cat)), ...)
```

### 安全设计

| 场景 | 处理 |
|------|------|
| GlobalModifierManager 未挂载 | 所有注入点带 `Instance != null` 防空，回退到乘数=1 |
| Dictionary key 不存在 | `TryGetValue` 模式，不存在初始化为0再累加 |
| 多Buff同时修改同字段 | 加性叠加 `1.0 + Σ(v-1.0)`，防止乘法爆炸 |
| 存档/读档 | 仅持久化 Buffer ID+天数，加载时从 SO 重建 MasterPayload |
| SO数值热更新 | 修改 SO 后下次加载自动生效（不缓存 SO 数据） |
