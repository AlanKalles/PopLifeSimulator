# 地板放置系统设计文档

## Context
当前 FloorGrid 是固定尺寸的预制网格，玩家直接在上面放建筑。目标是让"地板"本身成为可放置物品——玩家需要先铺设不同尺寸的矩形地板瓦片，再在有地板的区域放建筑。

## 设计决策
- **级联处理**：禁止操作 — 地板上有建筑时不可移动/拆除，必须先手动清空
- **地板形状**：仅矩形 — 用 `Vector2Int tileSize` 定义
- **地板类型**：纯尺寸差异 — 视觉统一
- **世界边界**：保持固定 gridSize，不做扩展
- **地板 Prefab**：每种尺寸一个独立 prefab（完整成品美术，含地板面、天花板、外观等）
- **横向连接**：FloorTile 可以左右横向相连，相连面格子数必须一致（所有 floor 高度相同）
- **防悬空保护**：不可移动/销毁一个 FloorTile，如果它是上方某个 FloorTile 的唯一支撑

---

## 架构变化总览

```
变化前:
  FloorGrid [Cell[,] 20x10]
    → 建筑直接放在网格上
    → 放置规则: y=0 + 列独占

变化后:
  FloorGrid [Cell[,] 20x10]  (不变)
    + floorTileLayer [bool[,] 20x10]  (新增)
    + floorTileInstances (独立字典)    (新增)
    → 先铺地板瓦片，再在地板上放建筑
    → 放置规则: 建筑所有格子必须在地板上
```

## 2. FloorGrid 变化
文件: `Scripts/Runtime/FloorGrid.cs`

### 新增数据
```csharp
private bool[,] floorTileLayer;                                    // 哪些格子有地板
private string[,] floorTileOwnerId;                                // 每格属于哪个 FloorTileInstance
private readonly Dictionary<string, FloorTileInstance> floorTileInstances = new();  // 独立字典
```

### 移除
- `columnsWithGroundBuildings` HashSet 及 MarkOccupied 中的列追踪逻辑
- `CanPlaceFootprint()` 中的 y=0 规则和列独占规则

### 新增方法
| 方法 | 功能 |
|------|------|
| `CanPlaceFloorTile(fp, origin)` | 检查范围 + 无地板重叠 + 支撑/连接规则 |
| `PlaceFloorTileTransactional(arch, pos, rot)` | 创建实例 + 标记 floorTileLayer |
| `RemoveFloorTile(instance)` | 前置检查：无建筑 + 不会导致悬空 → 清除 |
| `MoveFloorTile(instance, newPos, newRot)` | 前置检查：无建筑 + 不会导致悬空 + 新位置合法 |
| `HasBuildingsOnFloorTile(instance)` | 检查地板上是否有建筑 |
| `GetBuildingsOnFloorTile(instance)` | 返回地板上所有建筑列表 |
| `WouldBreakSupport(instance)` | 检查移除/移动此地板是否会导致上方或横向地板悬空 |
| `AreAdjacentFloors(a, b)` | 检查两个 FloorTile 是否共享垂直边界（相邻楼层） |
| `HasFloorTileAt(Vector2Int pos)` | 单格查询 |
| `RebuildFloorTileLayer()` | 从 floorTileInstances 重建 bool 层（加载存档用） |
| `AllFloorTiles()` | 枚举器，遍历所有地板实例 |

### 修改 `CanPlaceFootprint()` (建筑放置验证)
```
旧: ✓ y=0 + ✓ 范围 + ✓ 未占用 + ✓ 列未被 y=0 建筑占
新: ✓ 范围 + ✓ 未被建筑占用 + ✓ 所有格子有地板 (floorTileLayer[x,y] == true)
```
`CanPlaceFootprintAllowSelf()` 同步修改。

### 修改 `MarkOccupied()`
移除 `columnsWithGroundBuildings` 相关逻辑。

### 修改 `Init()` / `RebuildFromScene()`
- `Init()`: 同时创建 floorTileLayer 和 floorTileOwnerId 数组
- `RebuildFromScene()`: 先注册地板（FloorTileInstance），再注册普通建筑

### 修改 `RegisterAllChildBuildings()`
在遍历中加类型分支：
- `building is FloorTileInstance` → 路由到 floorTileInstances + 标记 floorTileLayer
- 其他 → 走现有 instances 注册路径

## 3. ConstructionManager 变化
文件: `Scripts/Runtime/ConstructionManager.cs`

### Place 模式
- `arch is FloorTileArchetype` → 用 `CanPlaceFloorTile()` 验证 + `PlaceFloorTileTransactional()` 放置
- 其他 → 现有逻辑（使用修改后的 CanPlaceFootprint）
- Preview 系统：**直接复用**（prefab 有 SpriteRenderer，正常工作）

### Move 模式
- Raycast 检测到 `FloorTileInstance` 时，按序检查：
  1. `isDefault` → true: 禁止（默认一楼不可移动）
  2. `WouldBreakSupport()` → true: 禁止（移除会导致上方/横向地板悬空）
  3. 通过 → 带着上面的建筑一起移动（计算偏移，整体验证新位置）
- Raycast LayerMask 需包含 "FloorTile" layer（在移动/拆除模式下）

### Destroy 模式
- 检测到 `FloorTileInstance` 时，按序检查：
  1. `isDefault` → true: 禁止
  2. `HasBuildingsOnFloorTile()` → true: 禁止（先清空建筑）
  3. `WouldBreakSupport()` → true: 禁止（会导致悬空）
  4. 通过 → 正常拆除确认流程

## 4. 隔离措施（防止干扰现有系统）

### 4.1 独立字典
地板存在 `floorTileInstances`，不进入 `instances`。
→ `AllBuildings()`, `AllShelves()`, `AllFacilities()` 完全不受影响
→ DayLoopManager, StatsDataManager, QuestProgressTracker 等零修改

### 4.2 独立 Layer
地板 GameObject 使用 "FloorTile" Layer（需在 Project Settings 中创建）。
→ BuildingInteractionManager 的 `buildingLayerMask` 不包含此 Layer
→ 鼠标悬停/点击不会在地板上触发 InfoBubble 或 DetailPanel

### 4.3 ConstructionManager 分支
通过 `is FloorTileArchetype` / `is FloorTileInstance` 类型检查进入不同代码路径。
→ 放置、移动、拆除各有独立逻辑

## 5. 寻路同步

- 地板放置时：更新 GridGraph walkability → 新区域变 walkable
- 地板移除时：更新 GridGraph walkability → 区域变 unwalkable
- 无地板格子 = unwalkable → 顾客只在有地板区域行走
- 相邻地板自然连通，间隔不可通行

### ⚠️ A* Pathfinding 关键注意事项

1. **修改节点必须在安全上下文中执行**：`node.Walkable` 赋值和 `CalculateConnections()` 必须包裹在 `AstarPath.active.AddWorkItem(new AstarWorkItem(...))` 中，否则 A* 会抛异常并停止扫描。
2. **GridGraph 2D 模式**：需设置 `gridGraph.rotation = new Vector3(-90, 0, 0)` 或 `gridGraph.is2D = true`（取决于版本）。
3. **禁用碰撞/高度检测**：walkability 由程序化控制时，必须设置 `collision.mask = 0`、`collision.heightMask = 0`、`collision.unwalkableWhenNoGround = false`、`collision.heightCheck = false`，否则 A* 的碰撞/高度检测会覆盖程序化设置。
4. **同步流程**：
   ```
   astarPath.AddWorkItem(new AstarWorkItem(ctx => {
       // 第一步：设置所有节点 walkability
       gridGraph.GetNodes(node => {
           node.Walkable = hasFloor && !hasBuilding;
       });
       // 第二步：重新计算连接
       gridGraph.GetNodes(n => gridGraph.CalculateConnections((GridNodeBase)n));
   }));
   ```
5. **跨 FloorTile 连接规则**：
   - 使用单张 GridGraph 覆盖所有楼层
   - 同步 walkability 后，第三步遍历所有节点，断开不合法的跨 FloorTile 连接：
     - **垂直方向（dir 0,2,4,5,6,7）**：如果两节点属于不同 FloorTileInstance → `SetConnection(dir, false)` 断开。上下穿行只能通过电梯（NodeLink2）
     - **水平方向（dir 1,3）**：如果两节点属于不同 FloorTileInstance → 检查横向连接合法性（相连面格子数一致）→ 合法则保持连接，不合法则断开
   - 电梯通过 NodeLink2 实现离网连接，不受网格连接断开影响

### 横向连接规则
- 两个 FloorTile 可以横向相连（左右紧贴），顾客可以自由穿行
- **条件**：相连面的格子数必须一致（所有 floor tile 高度相同，所以左右紧贴时整个接触边的格子数自然匹配）
- **判定**：FloorTile A 的右边缘列 与 FloorTile B 的左边缘列 在 y 范围上完全重合
- 不满足条件时（如 A 高3格，B 高5格 → 接触面不一致），水平连接也会被断开

### 防悬空保护
- 移动或销毁 FloorTile 前，必须检查 `WouldBreakSupport(instance)`
- 检查逻辑：
  1. 收集该 FloorTile 所有格子 → `cellsToRemove`
  2. 找所有**上方直接依赖**的 FloorTile（底行某格的 y-1 在 `cellsToRemove` 中）
  3. 对每个依赖的上方 FloorTile：排除 `cellsToRemove` 后，检查底行是否还有至少一格支撑
  4. 找所有**横向直接依赖**的 FloorTile（紧贴的侧边在 `cellsToRemove` 中）
  5. 对每个依赖的横向 FloorTile：排除 `cellsToRemove` 后，检查它是否还有支撑（底部或其他横向连接）
  6. 任一依赖 FloorTile 失去全部支撑 → 返回 true（禁止操作）

## 6. 电梯系统

### 核心概念
- 电梯是跨楼层的传送通道，连接两个不同 FloorTile 上的格子
- 使用 **NodeLink2** 实现离网连接（不依赖网格相邻关系）
- 电梯占 buildingCells 层（和 shelf 同层互斥）
- 顾客穿行时不可见

### 放置规则
- 两端必须在**不同 FloorTileInstance** 上
- 两端所属 FloorTile 必须是**相邻楼层**（共享垂直边界：上方 tile 底行的 y-1 属于下方 tile）
- 不可跨楼层直达（1楼→3楼），除非中间楼层已有电梯
- 两端**不需要垂直对齐**（可以不同 x 位置）
- 两端格子必须有地板，不能有非电梯建筑

### 电梯复用与多连接
- 一个电梯格可以连接**多个**上下电梯（多条 NodeLink2 共用同一格子）
- 放置新电梯时，可以选择已有电梯格作为端点 → 复用该格，不重复创建视觉标记
- 移除某条连接时，只有当该格子不再被任何电梯使用时才释放 buildingCells

### 寻路整合
- 网格层面：跨 FloorTile 的垂直连接已被断开（第5章）
- 电梯层面：NodeLink2 提供离网连接，A* 自动将其纳入寻路计算
- 无电梯时顾客无法上下楼 → 寻路失败

### 顾客可见性
- 顾客进入电梯格且正在移动时 → 隐藏 SpriteRenderer
- 离开电梯格或到达目标后 → 恢复可见

### 数据结构
```
ElevatorData:
  bottomPos (Vector2Int)    // 下层格子
  topPos (Vector2Int)       // 上层格子
  nodeLink2 (GameObject)    // NodeLink2 组件所在的 GO

FloorGrid 新增:
  List<ElevatorData> elevators
  PlaceElevator(bottom, top) → 验证 + 占格 + 创建 NodeLink2
  RemoveElevator(pos) → 释放格子（检查复用） + 销毁 NodeLink2
  IsElevatorAt(pos) → 查询
```

## 10. Sprite 与网格对齐

### 对齐规则
- Prefab 实例化在 `GridToWorld(pos)` = footprint 左下角格子的世界位置
- `footprintPattern` 从 (0,0) 到 (tileSize.x-1, tileSize.y-1)
- Sprite 需要从放置点向右(+x)和向上(+y)覆盖 `tileSize * cellSize` 的面积

### 实践方式
1. Sprite 的 Pixels Per Unit 确保世界尺寸 = tileSize × cellSize
2. Sprite Pivot 设为左下角 (0, 0)
3. Prefab 中 SpriteRenderer local position = (0, 0)
4. 在 Scene 中对着 FloorGrid 的 Gizmo 网格验证对齐

## 11. 预设多层楼

### 设计
- 设计师可在 Inspector 中预设多个楼层的 FloorTile（一楼、二楼等）
- 每个预设地板有 `isDefault` 标记，只有一楼设为 `isDefault = true`（不可移动/拆除）
- 其他预设楼层（二楼等）`isDefault = false`，玩家可以移动/拆除
- 预设地板在场景加载时自动放置

### 实现方式
```
FloorGrid 或 FloorManager 中:
  [Serializable]
  public class PresetFloor {
      public FloorTileArchetype archetype;
      public Vector2Int position;
      public int rotation;
      public bool isDefault;  // 仅一楼为 true
  }

  [SerializeField] private List<PresetFloor> presetFloors;
```
- `Start()` 时按列表顺序放置（一楼最先）
- 堆叠规则仍然生效（二楼必须底部有一楼支撑）

## 12. 装饰物系统

### 核心设计
- 装饰物是**独立于建筑的第三层**（地板层 → 装饰层 → 建筑层）
- 装饰物有自己的 `decorationCells` 数据，与 `buildingCells` 完全独立
- 装饰物和 shelf 可以在同一格共存（不互斥）

### 数据层
```
FloorGrid 三层数据:
  floorTileCells     (HashSet<Vector2Int>)   // 哪些格子有地板
  decorationCells    (HashSet<Vector2Int>)   // 哪些格子有装饰物
  buildingCells      (HashSet<Vector2Int>)   // 哪些格子有建筑(shelf/facility)
```

### 装饰物放置规则（三类）

| 类型 | 放置限制 | 示例 |
|------|---------|------|
| **边缘装饰** | 只能放在 FloorTile 的边缘格子（无相邻地板的边） | 栏杆、盆栽、门框 |
| **任意装饰** | 可以放在 FloorTile 的任意格子上 | 地毯、灯光、标识牌 |
| **非展示面装饰** | 可以放在 FloorTile 上，但不能在展示面格子上 | 墙面挂件、收纳架 |

### DecorationArchetype SO
```
DecorationArchetype : ScriptableObject
├── PlacementRule 枚举: EdgeOnly / Anywhere / NonDisplay
├── footprintPattern (占格)
├── prefab
├── buildCost
└── 其他属性（纯装饰 or 有 appeal 加成等）
```

## 13. 展示面（Display Face）系统

### 概念
- FloorTile 的 sprite 包含墙壁、边缘、玻璃等视觉元素
- **展示面** = 玻璃所在的格子（顾客从外面可以看到商品的区域）
- 展示面信息存储在 FloorTileArchetype 中，设计师在编辑器中标记

### FloorTileArchetype 扩展
```
FloorTileArchetype 新增:
├── List<Vector2Int> displayFaceCells   // 展示面格子（相对 footprint 原点）
└── OnValidate() 中确保 displayFaceCells ∈ footprintPattern
```

### 编辑器 Inspector
- 类似 `FootprintPatternEditor`（现有的 shelf 占格编辑器），提供图形化网格界面
- 在 tileSize 定义的矩形网格上，设计师可以：
  - 点击格子标记为"展示面"（特殊颜色，如橙色）
  - 普通格子保持默认颜色
- 两套数据在同一编辑器界面中显示：footprint（蓝色）+ 展示面（橙色叠加）

### 运行时查询
```
FloorGrid 新增方法:
  bool IsDisplayFace(Vector2Int worldPos)   // 查询某格是否是展示面
  → 查找该格属于哪个 FloorTileInstance → 检查 displayFaceCells
```

### 与装饰物的交互
- `PlacementRule.NonDisplay` 类型的装饰物放置时：检查目标格子不在 `displayFaceCells` 中
- `PlacementRule.EdgeOnly` 类型：检查目标格子是 FloorTile 的边缘且不在展示面上

## 14. 常驻网格线框系统

### 设计目标
玩家在游戏运行中始终能看到网格线框，直观了解空间划分、建筑占格、可用空间。
参考：Megamall Story（开罗游戏）的常驻网格。

### 技术方案：Tilemap 纯视觉叠加

Tilemap **仅渲染网格线框**，不参与游戏逻辑。现有的地板/建筑/预览全部保持 SpriteRenderer 不变。

```
渲染层级（从下到上）：
  背景图 (StoreBackgroundLayer)
  网格线框 Tilemap (新 sorting layer，低于 ShelfLayer)   ← 常驻
  地板 prefab (SpriteRenderer)
  状态叠加 Tilemap (新 sorting layer，高于地板)          ← 建造模式时显示
  建筑 prefab (ShelfLayer)
  建造预览 (FRAME layer)
```

### Tile 资产

只需制作 **2 种 tile sprite**（像素风格，匹配 cellSize 的 PPU）：

1. **线框 tile** — 四边 1px 细线，内部完全透明，白色/灰色
2. **色块 tile** — 纯色半透明方块（运行时通过 Tilemap.color 或多个 TileBase 控制颜色）

### 双层 Tilemap

#### 第一层：常驻线框（始终可见）
- 极低透明度（alpha 10-15%），不抢视觉焦点
- 只在有 FloorTile 的格子上显示
- 地板放置/移除时自动刷新
- 快捷键（如 G）可切换显隐

#### 第二层：状态叠加（建造模式 / 可切换）

| 状态 | 颜色 | 说明 |
|------|------|------|
| 空地板 | 无色 | 不显示叠加 |
| 被 shelf 占据 | 淡绿 (alpha 20%) | 货架/设施占用 |
| 被电梯占据 | 淡黄 (alpha 20%) | 电梯格 |
| 展示面 | 淡橙 (alpha 15%) | 玻璃展示面 |
| 放置预览（合法） | 绿色 (alpha 40%) | 正在放的建筑 footprint |
| 放置预览（非法） | 红色 (alpha 40%) | 不可放置 |

- 进入建造模式 → 自动显示，线框透明度提升（10% → 25%）
- 退出建造模式 → 自动隐藏，线框恢复低透明度

### GridOverlayManager（新组件）

```
GridOverlayManager : MonoBehaviour
├── 引用: FloorGrid, Tilemap gridLineTilemap, Tilemap overlayTilemap
├── TileBase gridLineTile           // 线框 tile
├── TileBase[] stateTiles           // 各状态色块 tile
│
├── RefreshGridLines()              // FloorTile 变化时刷新线框层
├── RefreshOverlay()                // 建筑/电梯变化时刷新状态层
├── SetOverlayVisible(bool)         // 切换状态叠加层显隐
├── SetGridLineAlpha(float)         // 调整线框透明度
│
├── ShowPlacementPreview(fp, pos, valid)  // 放置预览
├── ClearPlacementPreview()
│
└── 订阅 FloorGrid.OnFloorChanged → 自动刷新
```

### 坐标对齐
- Tilemap 的 Grid 组件 cellSize 设为与 FloorGrid.cellSize 相同
- Tilemap 的 Transform.position 设为与 FloorGrid.OriginPos 相同
- 这样 Tilemap 的 cell (x,y) 与 FloorGrid 的 gridCoord (x,y) 一一对应

### 性能
- Tilemap Chunk Mode 自动批处理，数百格无性能问题
- 事件驱动更新（不轮询）
- 只在有地板的区域设 tile

4. 顾客只在有地板区域行走
5. 保存/加载后地板和建筑状态正确
6. 旧存档加载时自动生成兼容地板
